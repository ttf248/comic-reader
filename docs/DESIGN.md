# 界面设计与待办

本文集中维护当前设计约束、验证方法和未完成事项。具体样式以 [tokens.css](../frontend/src/styles/tokens.css)、[global.css](../frontend/src/styles/global.css) 和组件代码为准；快捷键契约见 [SHORTCUTS.md](./SHORTCUTS.md)。

整理依据为 `e2f7d87` 及之前的实现与 R11 结论。历史评审、已完成问题和前后截图说明保留在 Git 历史，不作为新的待办；本文中的历史测量也不代表本次重新验证的结果。

## 产品与交互原则

Local Gallery 是浏览、阅读本地照片、漫画与视频的个人画廊。优先级依次是接着读、随便翻翻、找到某一本。

- 内容封面承担视觉重点，首页首屏只有一个主角；框架标题不能压过内容标题。
- 页面靠留白、字号和字重分组，强调色只用于主操作、选中态和进度；边框与阴影主要用于浮层及必要的表单分组。
- 核心动作可由键盘、鼠标、触摸完成，悬停只提供增强。触摸设备上的关键按钮常驻，图标按钮有可访问名称。
- 未读、在读、已读来自真实活动数据，分别使用白点、进度条和完成标记，不编造状态。同一事实不在顶栏、正文与状态栏重复展示。
- 加载、读取失败、资源失效、筛选为空分别处理；失败可重试，保留已加载内容与已确认写入结果。空态提供真实可操作对象或下一步入口。
- 弹窗隔离背景交互并约束焦点；菜单支持方向键、Home/End 与 Esc，关闭后按焦点归属恢复来源。详细键盘行为只在快捷键文档维护。
- 保持个人本地工具的边界，不引入后台 KPI 面板、路径式首页、云分享入口或装饰性封面滤镜。

## 视觉与布局约束

### 共享样式

| 项目   | 约束                                                                                                 |
| ------ | ---------------------------------------------------------------------------------------------------- |
| 容器   | 统一使用 `.page-shell`，上限 1600px，左右留白 `clamp(16px, 2vw, 40px)`；禁止嵌套                     |
| 排版   | 正文通常 14–15px，卡片标题 14px，辅助信息至少 12.5px；中文不使用大写与大字距标签                     |
| 层级   | 首页内容主标题高于框架标题，区块标题约 17px；网格与列表共用字号阶                                    |
| 命中区 | 普通控件至少 28px，主操作 36px，触摸场景 44px；可扩大外层命中区而保持开关等外观尺寸                  |
| 颜色   | CSS 变量与 Tailwind 语义颜色统一管理；light / dark / system 和六套强调色均需可读，不在组件硬编码 hex |
| 对比度 | 文字至少 4.5:1，非文本图标至少 3:1；半透明角标使用主文字色，按背景照片最不利情况检查                 |
| 动效   | 使用既有时长、缓动与圆角 token，只做必要的位移、透明度和缩放；尊重 `prefers-reduced-motion`          |

自定义组件样式通常放在 `@layer components`，避免压过 Tailwind 的显示与响应式工具类。阅读器焦点环等明确需要覆盖工具类的规则是例外，应注明原因。新增颜色或任意值类后检查实际生成的 CSS；动态拼接的 Tailwind 类不会自动生成，配置变更后必要时重启开发服务。

### 首页与应用框架

- 顶栏依次承载全局库概况、搜索、帮助/主题等全局动作。侧栏为品牌、导航、在读内容、弹性留白、设置与随机入口；在读数据复用 dashboard，不下载全库摘要。
- 有在读内容时，主角为大封面、标题、进度和紧邻的“继续阅读”按钮；无在读时随机入口承担主操作，未读推荐独立成区。
- ≥1280px 的舞台左侧放主角，右侧分为“其余在读”和“未读”两段，共用 `.stage-grid` 的列宽，各段最多一行。列数与显示条数集中在 CSS 同一处，避免不一致的半行与两栏高度失衡。
- <1280px 时，封面与标题/操作并排，其余在读和未读向下堆叠；手机主封面宽 150px，其余在读退为四张缩略图带。平板标题列限宽，避免进度条横跨整屏。
- 主封面高度随可用视口连续变化：`clamp(240px, calc(100dvh - 440px), var(--stage-cover-max))`；上限通常 480px，≥1536px 为 528px。主操作必须在常用笔记本首屏内完整可见。
- 主角/次级封面高度比目标 ≥1.6，首屏高度受限时可降至约 1.5。调整次级列数时同时测量窄屏与短屏；收窄左栏会扩大右栏封面，可能反而削弱主角。
- 首页筛选条紧邻“全部图像”网格，只筛选该网格。只有一本在读、没有未读或没有在读等数据状态也必须检查，避免空出整栏。
- 顶栏带 blur 等样式时形成独立层叠上下文；下拉被正文遮住应检查父级层叠关系，不能只提高浮层自身的 z-index。

当前取舍：宽屏舞台仅显示 4–6 本“其余在读”，更多在读内容由侧栏列表承接；列宽随视口变化，主次比例允许在目标范围内浮动。

### 封面、列表与设置

| 场景             | 展示规则                                                                    |
| ---------------- | --------------------------------------------------------------------------- |
| 主角封面         | 2:3，大图使用 `/api/previews`，避免放大低分辨率缩略图                       |
| 全库、未读、最近 | 4:5 的密集网格；最近项附访问时间                                            |
| 收藏             | 2:3 的疏朗陈列                                                              |
| 图片卡片         | 按所在网格裁切，构图偏中上，保留封面标题和人物头部                          |
| 视频             | 纯视频网格使用 16:9；封面等比完整显示，留边使用恒深色媒体底，不对源图补黑边 |
| 年份时间线       | 16:9 单张代表封面，不在小格内拼马赛克                                       |

- 所有封面位处理 404、解码失败和抽帧中状态，使用有信息的占位，不能露出破图或无说明灰框。静态占位等待 ffmpeg 是正常降级。
- 星标与卡片链接平级，重试与播放按钮分离，避免嵌套交互元素及键盘误触；推荐位要求用户点星标时应让星标常驻。
- 列表按实际内容宽度容纳标题：≥1280px 双列、≥1600px 三列，缩略图、标题和右对齐计数仍在同一行，按从左到右再换行的顺序阅读。
- 设置页外层沿用全站容器保持内容左缘对齐，内层控制表单行长；≥1280px 双列并保持分组完整，窄屏标签与控件上下排列。缓存卡片等内层网格按容器宽度排布。

### 阅读器

- 画布、菜单、帮助、Toast、信息面板以及加载/失败状态均遵循深色阅读场景，浮层使用 `tone="reader"`，焦点环在深色背景上可见。
- 顶栏保留返回、名称、页码、收藏、全屏和更多；模式、适配、缩放、旋转等放在底部工具条。信息面板在宽屏与画布并排，窄屏位于顶栏下方，不能挡住返回按钮和翻页热区。
- 照片上的文字必须有覆盖整行文字的稳定深色底或蒙版；图标另加恒定局部底色。既检查祖先层蒙版，也检查靠负边距叠在照片上的兄弟层文字。
- 连续模式用按宽度生成的预览图，单张与双张保留原图以支持缩放。适应模式完整显示横图时允许留白，铺满由按宽等模式承担。

## 虚拟网格的关键约束

相册图片、视频与混合媒体网格当前均为 `overscan={720}`、`increaseViewportBy={{ top: 720, bottom: 720 }}`。相册摘要列表与阅读器连续模式使用各自参数，不能把这组数字套到所有列表。

- 窗口余量用于覆盖 VirtuosoGrid 约两行的底部估算误差，必须检查拖到底部后最后一行真实渲染，以及拖回顶部、远距离跳转与分页失败重试。
- `itemSize`、`fixedItemHeight` 属于 Virtuoso 列表接口，不能作为 VirtuosoGrid 的修复方案。
- 这组窗口值与偶发爆栈强相关。改动前后均运行 `audit:crash`，固定相册、访问次数、视口与缩略图来源，并同时复查末行；一次打开成功不足以证明修复。

R11 历史对照：405 项视频相册、生产构建、1280×720、`overscan=720`。这些是有限样本下的观察，不是无崩溃保证。

| `increaseViewportBy.bottom` | 崩溃次数 / 访问次数 |
| --------------------------- | ------------------- |
| 400                         | 6/12                |
| 480                         | 10/20、13/20        |
| 640                         | 7/12                |
| 720                         | 0/40                |

1600px 下沿曾导致整页爆栈；480px 的调整已撤回。较小窗口也可能增加崩溃，不能凭直觉调参。

## 验证方法

修改界面后按影响范围运行组件测试、布局/对比度审计和 E2E。整体布局调整需复查首页、最近、收藏、未读、设置、相册、标签、阅读器，覆盖 390 / 768 / 1024 / 1440 / 1920 宽度、明暗主题及网格/列表；舞台另查 1280×720、1366×768 等短屏。截图放 `frontend/.smoke/<任务>/`，不入仓。

在 `frontend/` 下运行，默认连接已启动的 `http://127.0.0.1:5173`；需要 Playwright Chromium（首次执行 `npx playwright install chromium`）：

```powershell
npm run audit:layout
npm run audit:contrast
npm run audit:contrast -- --self-test
npm run audit:crash
npm run shot -- --out .smoke/review
```

也可在仓库根目录使用独立临时媒体库，脚本构建并启动服务，E2E 后追加审计或探针：

```powershell
pwsh -NoProfile -File scripts/test-e2e.ps1 -Audit
pwsh -NoProfile -File scripts/test-e2e.ps1 -Crash
```

| 环境变量               | 使用范围与含义                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| `LG_BASE`              | 所有审计和截图；目标服务地址                                                                          |
| `LG_PAGES`             | 布局、对比度与截图；逗号分隔路由。仅布局/对比度支持 `album`、`reader`、`tag` 伪路由，截图需要实际 URL |
| `LG_THEMES`            | 布局、对比度与截图；默认 `light,dark`                                                                 |
| `LG_VIEWPORTS`         | 布局与截图；如 `390x844,1440x900`。对比度脚本固定 1440×900，不读取此变量                              |
| `LG_VIEWMODE`          | 布局与对比度；`grid` 或 `list`                                                                        |
| `LG_FULL`              | 截图；`1` 表示整页                                                                                    |
| `LG_CRASH_VISITS`      | 崩溃探针；访问次数，默认 10                                                                           |
| `LG_CRASH_ALBUM`       | 崩溃探针；指定相册名，默认选媒体最多的相册                                                            |
| `LG_CRASH_VIEWPORT`    | 崩溃探针；默认 `1280x720`                                                                             |
| `LG_CRASH_MOCK_THUMBS` | 崩溃探针；`1` 使用假缩略图，默认真实缩略图                                                            |

PowerShell 示例：`$env:LG_VIEWMODE = "list"` 后执行审计，结束用 `Remove-Item Env:LG_VIEWMODE` 恢复。上述变量只控制验证工具，不覆盖应用 YAML 配置。

截图工具默认只拍首页、最近、收藏和未读，且不包含 1024 断点；完整复核应显式设置页面与断点，不能把默认截图当作全站覆盖。标签审计优先真实标签，无标签才构造数据并注明；`-Audit` 的临时库包含中文、空格、`+`、`%` 等真实标签。阅读器审计应按相册 ID 直接进入，避免图片/视频入口文案差异导致漏页。

### 审计工具自身的验证

- 布局审计同时检查溢出、字号、命中区、有效内容宽与跨页内容左缘，阅读器不参与左缘比较。页面崩溃单独报错，不能算作空页面通过。
- 对比度使用文字 DOM、图片上文字像素、图标像素三条通道。背板按几何交叠与绘制顺序确定，不能只查祖先链；`elementsFromPoint` 会漏掉 `pointer-events:none` 蒙版。
- 像素包围盒须完全位于截图内，取样不越过背板；自身底色取中位数附近的簇，周边取贴字的四条直边，排除抗锯齿过渡带与圆角切角，避免药丸角标假阳性。
- 每增加判定路径都补已知好坏样本并运行 `--self-test`，不能通过放松标准、删断言或跳过失败页面制造通过结果。
- 有 SSE 的页面不要等待 `networkidle`；使用页面就绪及图片解码状态。截图后人工确认不是未加载封面；转发 API 时保留 method、headers、body，路径只匹配 `/api/`，避免拦截 Vite 的 `/src/api/` 源码。

现象：`Maximum call stack size exceeded`，react-virtuoso 网格状态发布递归，错误边界接管整页。已确认是既有问题；开发 StrictMode 下曾达 24/24，生产构建也曾发生。异步真实内容到达后的状态更新与虚拟窗口取值相关，根因尚未定位。

已具备 [崩溃探针](../frontend/scripts/album-crash-probe.mjs) 与上述参数对照。已尝试的 `scrollbar-gutter: stable`（12/20）和移除未加载占位槽（7/10）未解决；不能使用 VirtuosoGrid 不支持的 `fixedItemHeight`。历史上检查过上游 4.18.12–4.18.20 的日志，没有发现对应修复，这不代表今后版本的结论。

下一步：在真实媒体库持续复现，记录首轮渲染、异步分页与网格尺寸状态传播，再定位递归环。验收需在相同样本、视口、访问次数与缩略图来源下比较修复前后崩溃率，并通过末行、分页及真实全栈 E2E；0/10 或 0/40 只能说明该次样本未复现。
