# 设计目标、验证与待办

本文定义设计决策空间、质量要求与已知风险。现有 [tokens.css](../frontend/src/styles/tokens.css)、[global.css](../frontend/src/styles/global.css)、组件、截图及布局测试描述当前实现，均可随新的设计方案演进。快捷键契约见 [SHORTCUTS.md](./SHORTCUTS.md)。

## 设计决策权限

用户提出界面优化或重设计时，AI 应根据目标和实际内容形成完整方案，自行调整相关布局、组件和视觉系统。旧文档、旧注释与旧截图中的具体样式不构成继续沿用的要求。

- 可重新安排首页内容、导航、搜索、侧栏、阅读控制与设置页，允许拆分、合并或替换现有展示组件；改动范围由用户目标决定，不必局限为局部样式补丁。
- 可调整容器宽度、列数、断点、封面比例、字号阶、主题配色、材质、圆角、阴影与动效。现有 1600px 容器、1.6 倍封面比例、双栏舞台、固定列数和底部工具条都是可替换的方案。
- “内容优先”“克制”等表述用于判断效果，不限制品牌表达、色彩或排版探索。不预设只有冷灰、极简、纸面、单主角或整齐网格才适合本项目。
- 视觉值集中在 token/共享样式维护是工程约定；token 的值、主题方案与组件样式可以一起重做。复用现有组件是选择，不是设计目标。
- 路径安全、数据一致性、现有功能语义、可访问性和大库性能仍需保证。改布局不会自动授权删除功能、改变 API 或重置用户偏好；设计调整涉及交互时同步更新实现、测试及快捷键说明。

## 产品目标与质量要求

Local Gallery 帮助用户浏览、阅读本地照片、漫画与视频，重点任务是接着看、发现内容、找到目标。页面围绕任务组织，信息主次与操作优先级可因场景而变化。

当前方案以“照片是唯一的彩色”为视觉方向：界面外壳（画布、卡片、侧栏、描边、遮罩层）全部走无彩灰阶，页面里唯一有彩色的东西是照片本身；衬线标题与照片卡片继续保留书刊感，强调色由主题方案本身决定、不再单独切换。侧栏在明暗两主题下都是画面里最深的表面，靠一条 hairline 与画布分隔。首页使用横向阅读区、独立四本未读预览与紧凑年份索引；其余在读通过有限预览和最近页承接。封面画幅按工作台分侧：照片方形、漫画竖版。这是当前设计选择，可继续演进。

最近、收藏和未读页使用带场景提示的统一页头；相册与视频详情采用封面、信息和操作相邻的摘要，标签页将标题统计与照片分栏。设置使用独立分组面板与窄屏堆叠表单，阅读器使用中性暗场和浮动控制条，信息面板让开顶部操作。照片工作台没有未读与在读区，漫画工作台才有。两个工作台的基调也各成一套：照片侧冷（冷调品牌点缀 + 方形封面，像展陈墙），漫画侧暖（暖调点缀 + 竖版封面，像书脊）；差异只落在品牌色与 hero 面板底色两处，画布与文字保持中性灰阶。首页首屏专区同样各成一套：漫画是「继续阅读 / 未读」，照片是「最近加入 / 随手看看」；索引维度一个是年份，一个是作品。所有变化保持原有数据与快捷键语义。

| 设计维度     | 自主决策空间                                 | 验收关注                                                                                         |
| ------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 信息架构     | 区块顺序、导航形式、搜索位置、分组与内容密度 | 用户能理解页面并找到高频操作，信息与动作相邻，重复入口有实际用途                                 |
| 视觉语言     | 色彩、排版、图形、表面层次、留白与动效       | 形成有辨识度且连贯的表达，文字层级可读，视觉重点与当前任务一致                                   |
| 响应式布局   | 流体或限宽容器、不同页面的网格、列数与断点   | 宽屏空间利用合理，窄屏仍有完整操作路径，没有意外溢出、遮挡与失衡空洞；不要求所有页面内容左缘相同 |
| 媒体呈现     | 不同画幅、裁切、陈列、视频与图片的区分方式   | 重要内容保留清楚，大图分辨率足够，失败有解释，不改写用户原始媒体                                 |
| 阅读器       | 画布明度、控件位置、常驻或按需出现的层次     | 阅读舒适，控件容易发现且不挡翻页热区，图片/视频操作及偏好恢复正常                                |
| 主题与无障碍 | 重做视觉 token 与主题表达、键盘和触摸呈现    | 明暗主题均可读，文字/图标对比度达标、命中区足够、焦点可见，支持减少动态效果与离线使用            |

加载、读取失败、资源失效与筛选为空应可区分；未读/在读/已读来自真实数据，表现形式可重新设计。异步操作保留已加载内容与已确认结果，错误可重试。模态隔离、焦点恢复、快捷键与触摸操作是交互质量，不限定组件外观或固定位置。

### 视觉系统：字号、圆角与语义色

视觉值只有一份来源：`tokens.css` 定义，组件不写死数值。Tailwind 的 `borderRadius` / `fontSize` 映射到同一批 CSS 变量，因此 `rounded-lg` 与 `var(--radius-tile)` 指的是同一个值。

**字号阶梯**（`--text-*`）每一档只承担一个角色：

| 档 | 值 | 角色 |
| --- | --- | --- |
| `--text-badge` | 11.5px | 徽章、键帽 —— **只允许拉丁字母与数字**；带汉字的徽章（转码状态、标签、导航分组名）一律升到 `--text-meta` |
| `--text-meta` | 12.5px | 次要信息：时间、来源、计数 |
| `--text-body` | 14px | 正文、元信息行、按钮与输入的文字 |
| `--text-label` | 16px | 卡片标题、列表行标题 |
| `--text-section` | 21px | 区块标题 |
| `--text-page-sm` | 28px | 次级页标题：最近 / 收藏 / 未读 / 设置 / 标签 / 相册 |
| `--text-page` | 42px | 工作台首页标题 |

中文正文不低于 12.5px。原先卡片标题停在 14px，与区块标题 21px 之间空着一档，标题撑不起视觉锚点 —— `--text-label` 就是补上的那一档。随视口缩放的展示字号（hero 标题、相册摘要标题）用 `clamp()`，两端是唯一允许的硬编码。

**圆角阶梯**（`--radius-*`）按形状命名而不是按大小编号：编号式命名会让同一个数值在不同语境里被当成不同含义，于是组件里开始出现 11px / 14px / 18px 这类硬编码。`--radius-xs` 4 / `--radius-media` 8 / `--radius-control` 12 / `--radius-tile` 16 / `--radius-panel` 22。书脊造型（品牌方块、漫画封面、空态图标）的非对称圆角是造型不是尺寸，单独注明。

**语义色分工**：`--brand` 跟着工作台模式走（照片冷、漫画暖），只出现在品牌标记、页眉眉标、章节序号与焦点环。`--favorite` 是收藏专用色，**不跟模式走** —— 收藏是全局一份数据，颜色也该全局一致；它同时避开 `--warning`（扫描告警）与 `--brand`，否则「琥珀色」会同时意味着三件事。`--warning` 只表示扫描与加载告警。

**焦点环**：用 `--focus`（即品牌色）而不是 `--accent`。`--accent` 在浅色主题里是近黑的石墨色，压在深色照片上就是一条看不见的黑边。焦点环不写 `border-radius` —— `outline` 会自己跟随元素的圆角。

### 视觉验收

- 先说明这次设计要改善的用户体验和视觉方向，再用实际页面验证。避免把“加大封面、排列卡片”当作全部设计，也不要仅为填空白增加无关模块。
- 从完整页面判断信息结构、主次、图文比例、密度、留白节奏与跨页连贯性；允许有意图的非对称和不同页面布局。旧截图用于对比问题，不要求像素还原。
- 使用横/竖图、视频、长标题、少量/大量内容及空态等真实数据状态检查方案，不能只在理想样本下成立。
- 截图检查与功能验证共同形成结论。脚本能发现溢出、对比度或崩溃，不能证明界面好看；审计全绿和历史“已验收”都不能替代当次视觉判断。

### 实现与测试如何演进

当前 `.page-shell`、`.stage-grid`、导航与阅读器位置属于样式实现。重新设计时可替换这些约定，同时处理容器嵌套的内边距、flex 收缩、浮层层叠上下文和 Tailwind 样式生成等实际问题。

组件测试中的区块位置、E2E 中的列数和布局审计中的跨页左缘一致，属于相应方案的回归基线。采用新设计时，同步更新布局断言和审计适用范围，保留相册可打开、模式可切换、数据正确、键盘可用等行为验证，在提交说明中解释变化；不能只跳过失败或删除验证来制造通过结果。

## 工作台模式与内容属性

媒体目录有两种内容属性，它们是两种产品，不是同一套交互换皮：

| | 照片目录 | 漫画目录 |
| --- | --- | --- |
| 入口 | 点击相册直接进入照片墙 | 点击相册直接进入阅读器 |
| 主画面 | 按真实宽高比自适应排布的平铺网格 | 单张图片适应屏幕 |
| 交互 | 点开大图、缩放、拖动、全屏、上一张 / 下一张 | 翻页、连续滚动、双页、RTL / LTR、缩放、适配 |
| 状态 | 不留进度 | 阅读进度（读到第几页）、已读 / 未读、双页计数 |
| 偏好 | 密度等照片模式偏好 | 阅读模式、适配方式、翻页方向等阅读器偏好 |

属性只由所属媒体根决定，互斥且只能选一个；目录下的相册与集合一并继承，不按图片数量推断，也没有单本相册的归类动作。两类的偏好与导航互不污染：偏好分存在不同的浏览器存储里，进度只有漫画才有，因此照片那边不存在「进度被另一种用途污染」的问题。

照片墙的视觉基调跟随应用主题（它是浏览页），大图预览是暗场浮层（它是沉浸场景）；阅读器整屏暗场，浮层与控件用白色系。两者不共享同一套外壳。

### 全局工作台模式

上面两种内容各自自洽，但它们此前混在同一套列表里：首页、最近、收藏、未读、标签与侧栏是一份混合清单，照片相册与漫画相册的卡片长得一模一样，点开却是两套语境完全不同的画面，漫画词汇（「继续阅读 / 未读 / 读完」）又套在照片上。这就是「不伦不类」的来源。

工作台模式（`appMode`）就是目录的内容属性，取值 `photo` / `comic`，两档互斥，存在服务端偏好里：

| | 照片工作台 | 漫画工作台 |
| --- | --- | --- |
| 侧栏入口 | 照片库 / 最近浏览 / 收藏照片 | 漫画库 / 未读 / 最近阅读 / 收藏漫画 |
| 列表内容 | 只列照片目录的相册 | 只列漫画目录的相册 |
| 首页专区 | 最近加入 / 随手看看 | 继续阅读 / 未读 |
| 索引维度 | 按年份（时间线） | 按作品（作品索引） |
| 继续 | 无 | 继续阅读 |
| 未读 | 无 | 未读 |
| 卡片完成态 | 无 | 已读完 |
| 卡片进度 | 无 | 百分比 |
| 封面画幅 | 方形（展陈墙） | 竖版（书脊） |
| 色调 | 冷 | 暖 |

侧栏品牌区下方是「照片 / 漫画」分段控件，下面只列当前模式自己的入口：照片模式是「照片库 / 最近浏览 / 收藏照片」，漫画模式是「漫画库 / 未读 / 最近阅读 / 收藏漫画」。两套菜单完全隔离——漫画那边没有「继续浏览」「未浏览」，照片这边也没有「未读」「已读完」。

隔离不止停在菜单上：模式进 URL 路径，两侧各有自己的路由。照片侧是 `/photo`、`/photo/recents`、`/photo/favorites`、`/photo/albums/…`、`/photo/tags/…`，漫画侧是 `/comic`、`/comic/unread`、`/comic/recents`、`/comic/favorites`、`/comic/albums/…`、`/comic/tags/…` 与漫画阅读器 `/comic/read/…`。这样切模式就是一次普通导航，浏览器前进后退能跨模式，深链也能直接分享；相册的链接永远落在它自己所属的那一侧。

切换模式时能一一对应的只有两侧都有的同名页（最近 / 收藏 / 标签）：相册与阅读器只属于一侧，未读只属于漫画侧，因此它们都回落到对侧首页。

没有第三档「全部相册」：不过滤的一档会让两个模式的菜单互相掺入，用户又要重新分辨哪个入口属于哪边。属性由目录决定，工作台一次只面对其中一半，另一种相册在这个工作台里根本不出现。

隔离要彻底到「另一侧的东西连提都不提」。收藏与历史是全局一份数据（相册、集合、智能标签混在一个列表里），但每个工作台只呈现属于自己这一侧的部分，界面上也不出现「另有 N 项属于其它类型」这类提示——那等于把另一侧的存在又提醒了一遍。

由此带出一条必须守住的判定：**「这一侧看不到」不等于「失效」**。只含漫画的标签被收藏后，在照片工作台里查不到它，但它没有失效，清理失效收藏的动作绝不能把它删掉。失效只表示「库里已经没有这个资源」。这条判定错了就是一次真实的数据丢失，所以它有自己的回归用例。

集合继承所属目录的属性，因此同样参与过滤：漫画目录下的集合不会出现在照片工作台里。它的「作品数」恒为全部后代，但集合的所有成员都在同一媒体根（同属性），所以这个计数天然按侧，不需要再拆一份按属性的计数。集合与标签卡片的计数单位也跟着那一侧走：照片侧说「本」，漫画侧说「卷」。

阅读器整屏脱离 AppShell，侧栏不可见，所以阅读器顶部提供一枚工作台 chip：切模式意味着离开阅读器回到外壳。

帮助浮层跟着模式走：全局操作的措辞随工作台变化（照片工作台是「回到照片库 / 最近浏览 / 收藏照片」，漫画工作台是「回到漫画库 / 最近阅读 / 收藏漫画」），只属于一个模式的快捷键（例如未读页的 `U`）在另一个模式下不列出。照片墙额外多一组大图预览的操作。模式切换刻意不占快捷键——常见候选键都被浏览器的开发者工具或打印占用，而侧栏与设置页都是一步可达的控件。

### 两侧各成一套的首页与视觉

两个工作台不只是菜单不同：首屏给的东西、翻找的维度、卡片的样子都该不同，否则「隔离」只做了一半。

**首屏专区对称而不雷同。** 漫画侧有「继续阅读 / 未读」，因为漫画有阅读进度与已读状态；照片侧没有进度可言，于是给「接着看 / 最近加入 / 随手看看」——上次打开过的那本、按业务日期倒序的最近照片相册，加一本随机的。两侧各占首页第一屏的同一位置，骨架共用（`home-overview` + `discovery-panel`），面板外壳也共用，但内容与措辞完全分开：漫画的封面是竖版书脊，照片是方形展陈。照片侧的空态推荐位同样按侧给：漫画推未读，照片推最近加入。

**照片侧三块专区的排布。** 宽屏下「接着看」占宽栏、「随手看看」占窄栏，照片墙移到第二行通栏——横贯一行更像一面展陈墙。没有浏览记录时（照片墙回到宽栏）版式与原来一致；窄屏只有一栏，三块按文档顺序单列排下。

**「接着看」的边界。** 它是漫画侧「继续阅读」的对称物：侧栏给一枚常驻条目，首页给一块首屏专区。照片相册其实一直在记访问历史，只是原先只有「最近浏览」页在用。照片不留浏览位置，所以「接着看」回到**相册**，回不到**具体某一张**——它的线索只有「上次浏览」这个时间，不画进度条，也不出现「读到第几张」。这条边界写在界面上，也写在实现里：照片侧不读阅读活动，因此没有可显示的页码。

**两侧的词各归各。** 计数单位与动作动词跟着内容属性走，不跟着「当前在哪个工作台」走：照片说「张 / 本 / 浏览」，漫画说「页 / 卷 / 阅读」。漫画侧的一张图就是阅读器里的「一页」，相册卡片与阅读器必须用同一个词；照片侧则从头到尾只说「张 / 本」。两侧共用的组件（悬停预览、搜索结果、集合页标题、属性弹窗）按每张卡自己的 `contentKind` 取词，取不到时按照片兜底。词表集中在 `utils/workbench.ts`，它是唯一真相源。

**索引维度跟着内容走。** 照片的天然维度是时间，所以按年份分组；漫画常常不以年份命名，一部作品横跨好几年，按年份分会把同一部作品拆散在好几处，因此漫画侧改按「作品」分组——集合就是作品。年份索引两边都留着（它筛的是下方网格，不只服务索引条本身）。

**视觉基调一冷一暖。** 差异只落在品牌点缀与 hero 面板底色两处（`--brand*` / `--feature-bg`，按 `:root[data-theme][data-mode]` 组合覆盖），画布、文字、描边保持中性灰阶——外壳无彩，彩色留给内容本身。封面画幅同样分侧：照片侧方形（展陈墙），漫画侧竖版（书脊）。模式写在 `<html data-mode>` 上，由 URL 路径推导，因此切模式就是一次普通导航，色调随之切换。

## 虚拟列表与媒体网格

相册摘要由 `AlbumGrid` 虚拟化。照片墙的每一行高度由自适应排布算法确定（宽高比来自服务端的像素宽高），`Virtuoso` 只按行虚拟化，不参与测量行高；行内保持服务端媒体顺序，向分页钩子回报时换算为原始媒体序号。

- 排布算法是纯函数（`components/wall/justifiedLayout.ts`）：一行能放下就继续放，放不下换行；每行等比缩放铺满容器宽度；行高夹在目标行高的上下限之间，竖图不会顶满屏幕；末行不满时保持目标行高，不为填满而把一张图撑成巨幅。
- 容器宽度变化（侧栏折叠、窗口缩放）时重排；已渲染的行不会因为后续页到达而跳动——排布是贪心的，后到的条目只会影响它自己所在的行。
- 未知尺寸退回默认比例（3:2），视频按 16:9；服务端给出真实像素宽高后即刻使用。

- 保留服务端总数对应的轻量占位槽（照片墙按默认比例占位），远距离滚动后持续补页，失败保留已加载内容并支持重试，不为整本相册挂载完整媒体 DOM。
- 页面留白与最大宽度放在虚拟列表外层，视口与列表保持同宽；行内间距计入行高，首尾不满一行的条目仍可到达。
- 照片墙使用 `overscan={600}` 和上下各 600px 的视口余量。`increaseViewportBy` 不能贪心：数值过大时 `Virtuoso` 的尺寸树会在一次测量里展开过深，触发「Maximum call stack size exceeded」，整页被错误边界接管。单元测试对这三个参数设了上限断言。阅读器连续模式使用独立参数。
- 修改虚拟化、窗口或容器后，检查拖到底部、返回顶部、远距离跳转、分页失败重试、断点与密度切换；运行 `audit:crash` 时固定相册、访问次数、视口和缩略图来源。单次打开或有限样本零崩溃不能证明所有场景都无异常。

## 验证方法

按影响范围验证：局部修改检查受影响组件、页面与断点，全局视觉系统或导航重做则复查首页、最近、收藏、未读、设置、相册、标签与阅读器。以 390 / 768 / 1024 / 1440 / 1920 宽度、明暗主题与网格/列表为起点，补查新方案的临界断点、短屏和数据状态，不固定各档版式。运行对应组件测试和 E2E，布局/对比度审计作为检查工具；涉及虚拟网格再跑崩溃探针。截图放 `frontend/.smoke/<任务>/`，不入仓。

在 `frontend/` 下运行，默认连接已启动的 `http://127.0.0.1:5173`；需要 Playwright Chromium（首次执行 `npx playwright install chromium`）：

```powershell
npm run audit:layout
npm run audit:contrast
npm run audit:contrast -- --self-test
npm run audit:crash
npm run shot -- --out .smoke/review
```

也可在仓库根目录使用独立临时媒体库，脚本构建并启动服务，E2E 后追加审计或探针：

```powershell
pwsh -NoProfile -File scripts/test-e2e.ps1 -Audit
pwsh -NoProfile -File scripts/test-e2e.ps1 -Crash
```

| 环境变量               | 使用范围与含义                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| `LG_BASE`              | 所有审计和截图；目标服务地址                                                                          |
| `LG_PAGES`             | 布局、对比度与截图；逗号分隔路由。仅布局/对比度支持 `album`、`reader`、`tag` 伪路由，截图需要实际 URL |
| `LG_THEMES`            | 布局、对比度与截图；默认 `light,dark`                                                                 |
| `LG_VIEWPORTS`         | 布局与截图；如 `390x844,1440x900`。对比度脚本固定 1440×900，不读取此变量                              |
| `LG_VIEWMODE`          | 布局与对比度；`grid` 或 `list`                                                                        |
| `LG_FULL`              | 截图；`1` 表示整页                                                                                    |
| `LG_CRASH_VISITS`      | 崩溃探针；访问次数，默认 10                                                                           |
| `LG_CRASH_ALBUM`       | 崩溃探针；指定相册名，默认选媒体最多的相册                                                            |
| `LG_CRASH_VIEWPORT`    | 崩溃探针；默认 `1280x720`                                                                             |
| `LG_CRASH_MOCK_THUMBS` | 崩溃探针；`1` 使用假缩略图，默认真实缩略图                                                            |

PowerShell 示例：`$env:LG_VIEWMODE = "list"` 后执行审计，结束用 `Remove-Item Env:LG_VIEWMODE` 恢复。上述变量只控制验证工具，不覆盖应用 YAML 配置。

截图工具默认只拍首页、最近、收藏和未读，且不包含 1024 断点；完整复核应显式设置页面与断点，不能把默认截图当作全站覆盖。标签审计优先真实标签，无标签才构造数据并注明；`-Audit` 的临时库包含中文、空格、`+`、`%` 等真实标签。阅读器审计应按相册 ID 直接进入，避免图片/视频入口文案差异导致漏页。

### 审计工具自身的验证

- 布局审计输出溢出、字号、命中区与有效内容宽；当前还将跨页内容左缘一致作为失败条件，阅读器除外。这是现有容器方案的检查，采用不同页面布局时需同步更新适用范围，不能直接作为新设计的统一要求。页面崩溃单独报错，不能算作空页面通过。
- 对比度使用文字 DOM、图片上文字像素、图标像素三条通道。背板按几何交叠与绘制顺序确定，不能只查祖先链；`elementsFromPoint` 会漏掉 `pointer-events:none` 蒙版。
- 像素包围盒须完全位于截图内，取样不越过背板；自身底色取中位数附近的簇，周边取贴字的四条直边，排除抗锯齿过渡带与圆角切角，避免药丸角标假阳性。
- 每增加判定路径都补已知好坏样本并运行 `--self-test`，不能通过放松标准、删断言或跳过失败页面制造通过结果。
- 有 SSE 的页面不要等待 `networkidle`；使用页面就绪及图片解码状态。截图后人工确认不是未加载封面；转发 API 时保留 method、headers、body，路径只匹配 `/api/`，避免拦截 Vite 的 `/src/api/` 源码。
