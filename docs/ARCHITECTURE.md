# 系统架构

## 设计目标

Local Gallery 是单用户、本机优先的媒体浏览器。系统保持“单 Go 进程 + 本地文件 + 浏览器持久化”的边界，不引入数据库、消息队列、微服务或额外反向代理。

核心约束：

- 后端独占媒体文件系统绝对路径，公共媒体 API 与前端媒体状态只使用稳定资源 ID。
- 开发期由 Vite 代理 `/api`；生产期由 Fiber 同端口托管静态资源和 API。
- 扫描、缩略图和视频处理允许后台执行，但必须支持取消、断连清理和有界并发。
- `config.yaml` 是唯一运行时配置源；命令行只允许选择配置文件。

## 分层与依赖

```text
React routes/components
        │
        ▼
API modules + TanStack Query + Zustand UI state
        │  resource IDs / JSON / SSE
        ▼
Fiber middleware → handlers → services → local files/cache
                         │          │
                         │          ├─ scanner / resource catalog
                         │          ├─ thumbnail / video pipeline
                         │          └─ scan cache
                         └──────────── prefs store
```

- `backend/cmd/server`：组合配置、服务、中间件、路由和进程生命周期，不承载业务规则。
- `backend/internal/middleware`：日志、恢复、local/LAN 访问门禁、资源 ID 解析和路径安全。
- `backend/internal/handlers`：HTTP/SSE 契约、输入校验、状态码和公共 DTO。
- `backend/internal/services`：扫描、资源目录、缓存、缩略图、faststart、转码和元数据。
- `backend/internal/pathutil`：配置、扫描、资源索引及缓存共用的根目录规范化与等价比较。
- `backend/internal/store`：低频偏好与高频媒体活动分文件并发访问，均使用原子落盘。
- `frontend/src/api`：唯一网络访问层；组件不手写端点。
- `frontend/src/store`：仅保存 UI 与会话状态；服务端数据由查询层管理。

依赖方向固定为入口 → handler → service/store → model。service 不依赖 Fiber，前端媒体组件只处理资源 ID；设置组件按下述本机管理例外临时持有配置路径。

## 资源标识与路径边界

扫描完成后，`ResourceCatalog` 从配置根目录和扫描树构建不可变索引：

| 前缀 | 资源     |
| ---- | -------- |
| `r_` | 媒体根   |
| `a_` | 相册     |
| `c_` | 集合     |
| `f_` | 媒体文件 |

ID 由根标识、资源类型和相对路径哈希生成；根目录与相对路径不变时 ID 稳定，且不能逆推出绝对路径。扫描发布时同时预计算 manifest、每个根/集合的直属子节点、全局相册摘要、节点 ID 映射、每本相册的自然排序媒体、标签及标签相册索引；分页与批量解析请求只校验游标或查表并复制结果，不再遍历或重排完整目录树。集合摘要在发布阶段聚合全部后代的相册数、媒体数与体积。请求进入 `/api/media/:id` 等路由后，资源中间件先解析 ID，再由路径安全中间件确认目标仍位于当前 `mediaRoots` 内。未知、过期或越权 ID 不进入文件服务。

配置页是明确的管理例外：`/api/config`、`/api/admin/fs/open` 和 `/api/admin/fs/directories` 可处理配置路径，但只接受回环请求。日志只输出目录 basename、逻辑缓存名和能力状态。

服务端配置表单按字段记录组合输入状态，媒体根按整组暂停自动保存，其他文本和数字配置只暂停当前字段。保存计时结果必须仍对应当前草稿快照才可提交，组合输入结束后从最终值重新计时，避免中间候选内容或旧计时结果提交、清除新输入。失焦确认组合输入，数字字段保持数值类型；删除输入项或离开页面会清理对应暂停状态与未提交计时任务，已发出的请求仍按原配置更新流程完成。

`useServerConfigSave` 使用 TanStack Query 的共享 mutation scope，在同一 QueryClient 中按发起顺序写入配置，覆盖离开后重新进入设置页的场景。表单显示优先级为编辑草稿、最新保存中值、失败输入、服务端确认值；状态也按当前可见值计算，旧响应不会给新草稿加上“已保存”提示。保存开始与确认时取消旧配置读取，防止后台 GET 回退已确认数据；读取传递 AbortSignal 并禁用 HTTP 缓存。LAN 凭据更新后的会话建立包含在串行保存流程中，完成前不发送后续配置写入；失败仍会释放流程，让后续保存按原错误处理继续。

失败输入按字段保存在 QueryClient 的内存缓存，保留 false、0 和空数组，不写入本地存储，不包含访问模式或令牌。重试只提交未被新草稿或排队写入覆盖的失败值，读取实时 mutation 状态避免重复点击；后续同字段保存成功会清除旧失败。显式重新读取仅在没有排队写入时执行，暂时禁用表单并暂停自动保存，成功后清除失败输入但保留其他草稿；失败、取消和卸载均不丢弃输入。读取使用独立取消信号与共享修订号，忽略取消或新写入之后的迟到响应。

网络错误、超时或 5xx 可能发生在服务端写入之后，媒体根对此保留结果待确认标记。后续根目录重试即使返回 `mediaRootsChanged=false`，或显式读取确认当前配置，仍删除客户端旧媒体库查询并提示重新扫描。该提示与失败记录共用会话内缓存，卸载后完成的写入也能在重新进入时提示；结果未确认、有新根草稿或保存仍在进行时禁用提示中的扫描按钮。Esc 只撤销本地输入，不承诺回滚已发生的服务端写入。

目录选择由后端 `BrowseDirectories` 解析真实路径并枚举直属目录，允许本机管理员浏览媒体根之外的位置。它每批读取 256 个条目，用固定 201 项的最大堆生成每页最多 200 项的有序结果，不缓存完整目录列表；Windows 磁盘根来自系统逻辑盘位图，前端不探测操作系统、不拼接路径。设置弹窗仅持有临时路径状态，导航时取消旧请求并忽略迟到结果，确认后才经现有配置更新流程保存，浏览或取消不修改配置。列表跳过文件、符号链接和 junction，显式输入的链接路径解析为真实目录；媒体内容 API 的资源 ID 与当前根路径校验不变。

## 访问边界

`AccessGate` 是 `/api` 的首个业务中间件，先于路径和资源 ID 解析。它校验 Host 与浏览器 Origin / Fetch Metadata，阻断 DNS rebinding 和跨源请求；`local` 模式随后失败关闭为回环限制，`lan` 模式只允许未认证访问最小化健康检查和会话端点。长连接使用同源 HttpOnly Cookie，不在 SSE URL 中放置令牌。会话只存在服务器内存中，8 小时过期，最多 256 个；令牌轮换通过摘要绑定使旧会话立即失效。配置管理器串行执行完整读改写事务，避免并发 PATCH 把新令牌覆盖回旧值。

`config.yaml` 含访问令牌和本机路径：Unix 启动加载与每次写入都会收紧为 `0600`；Windows 使用受保护 DACL，仅授权当前进程用户。无法收紧权限时配置加载或保存失败，避免凭据以宽松权限继续运行。

当前单端口服务器不终止 TLS，`lan` 的威胁边界是可信家庭网络；访问门禁防止误开放、未授权调用与浏览器跨源攻击，但不声称抵御同网段被动监听。面向不可信网络部署需要在未来显式加入 TLS，而不是把当前端口直接映射到公网。

## 扫描数据流

```text
POST /api/scans
  → StartOrReuse（全局最多一个活动任务）
  → prepareScanRoots（记录根身份与可读性）→ Scanner.scanRoots（可取消固定工作池 + 两阶段建树）
  → per-subscriber SSE broadcast
  → complete: 复核根身份与可读性、验证 scan generation → ResourceCatalog.CommitScan（结果 + ID/分页索引单指针发布）
  → ScanResultCache.Set（仅负责持久化）→ SSE complete(libraryRevision)
  → GET /api/library/manifest + cursor pages（单次 Acquire 读取固定 revision）
```

### 扫描器并发模型

`Scanner` 只启动 `min(8, NumCPU)` 个目录读取 worker。协调器动态派发发现的
子目录，worker 只返回目录记录，不递归等待子任务；枚举结束后再按路径关系
构建相册/集合树。因此并发数不随深度增长，也不存在父任务占满令牌后等待
子任务的死锁。默认完整递归；仅测试或内部调用显式给出 `MaxDepth` 时截断，
并在结果的 `warnings` 中说明。

扫描阶段使用本轮配置根的不可变路径 key 集合；遇到已单独配置的子目录根时，不加入父根的目录任务与子节点记录，由子根独立遍历。该集合只属于本轮局部 Scanner 副本，worker 只读，复用 Scanner 或调整根顺序不会残留旧边界。无需预遍历或两两比较根路径，常规目录发现时直接查表。最终实体树按最具体根分区，与资源索引的最长根匹配一致；子根本身只作为根节点，不产生额外集合包装层，SSE 相对路径也选择最具体根。

本轮开始时通过打开根目录、读取一个目录项及文件身份建立根快照，空根的 EOF 视为成功，不额外遍历目录树。同步入口和异步 runner 共用这份根身份；各根读取前后、整理后与 runner 提交前重新检查可读性，并以 `os.SameFile` 检测同一路径的新目录替换。根目录读取错误属于整轮失败；普通子目录读取失败先复核所属根，根仍有效才降级为告警。任一检查失败都不替换资源目录或扫描缓存。检查之间的外部文件系统改写不构成事务隔离，正常媒体增删也不被视为根身份变化。

目录工作池使用每个根独立的子 context。发生致命读取错误、取消或正常返回时统一取消子 context、关闭任务通道并等待全部 worker；结果发送同时监听该 context，避免提前失败后阻塞在已无人接收的结果通道。

### 资源 ID 翻译

`scan_cache.json`（schemaVersion=5）直接存 raw 绝对路径和根 ID 列表，但它只是重启恢复仓库，不作为 HTTP 请求的数据源。schema 不匹配时会隔离旧文件并冷启动。`ResourceCatalog` 是**唯一**负责把绝对路径翻译为 `r_/a_/c_/f_` 不透明 ID 的组件；它在私有内存中同时构建 raw 结果、ID 表和轻量分页索引，然后通过一次 `atomic.Store` 发布。

`CatalogSnapshot` 在请求开始时只 Acquire 一次。资源参数中间件解析 ID 时会把该快照 pin 到 Fiber Locals，handler 继续使用同一值。因此重扫可以在请求中途发布，但已开始的请求仍能完整解析旧快照。媒体根变更或清空库会递增 scan generation，取消旧任务并拒绝它稍后提交。

自定义封面在扫描产出候选结果后、库快照发布前叠加。覆盖文件必须仍在该相册的媒体索引中且真实存在；同一份覆盖会同步到顶层、嵌套集合和标签视图，因此重扫不会让卡片与详情封面分裂。

## 缓存读路径

后台维护在启动及每小时执行，只枚举 `derived/thumbnails`、`derived/converted`、`derived/video-faststart`、`derived/video-transcode` 的哈希命名完整产物。删除通过 `os.Root` 限制在派生根内，不跟随越界链接，不遍历 `state`，不处理临时文件；十分钟内的新产物保留。按年龄或全局容量软上限从旧到新淘汰，取消信号贯穿枚举和删除，退出等待维护任务结束。配置 `cacheMaxSizeMB: 0` 只关闭容量淘汰，不关闭过期清理。

`ScanResultCache` 内部用 `atomic.Pointer[scanResultSnapshot]`。
`Get` 走 `atomic.Load` 无锁，5k 相册 100+ 并发请求不再争夺 RWMutex。
写路径（`Set` / `ApplyCoverOverrides` / `SetWithOverrideApplied` /
`RebuildCoverForAlbum`）走 `atomic.Store` 或 CAS，CAS 失败重试基于最新
snapshot。stat 全部移到锁外，`flushDebounce=500ms` 异步落盘。
`dirtyVer` 与 `version` 配合（CAS 清零）保证 flush 期间并发 Set 不会
被错误标记为已持久化。

缓存恢复先按共用根规范化规则计算当前根 ID，再与缓存中的唯一根 ID 集合比较；等价路径和重复配置不导致健康缓存丢失，目录离线时也不额外探测文件系统。重复根 ID 或实体树中同 kind 的重复路径表示无效缓存，清除扫描缓存并由启动流程重新扫描，用户偏好与活动状态不受影响；持久化同样拒绝输出这两类重复，避免将重复统计写回磁盘。节点检查只遍历相册/集合实体树，允许同目录的虚拟相册与集合并存，标签视图可重复引用同一相册；健康缓存沿用当前 schema。

- 重复启动复用活动任务，不制造重复 I/O。
- 扫描 hook 保持当前根的目录读取计数，并携带根下标/根总数；相册数量累计所有已完成根与当前根，空根和混合目录的本目录媒体相册也按同一规则统计。根数来自本轮规范化、去重后的目录集合，不新增预遍历。
- 界面百分比是预估值：各根等分 0–95% 的读取预算，动态发现新目录时保持已报告值，整理阶段使用 99%，只有快照原子发布成功后报告 100%。取消与错误从最后发布的进度构建终态，保留数量、阶段和脱敏路径；最后一次读取回调中的取消也会在进入整理前生效。
- 每个 SSE 连接有独立缓冲，慢客户端不能阻塞扫描或抢走其他客户端事件。
- `StartOrReuse` 只创建或复用任务，不隐式创建事件通道；消费方通过 `Subscribe` 显式订阅并持有释放函数。启动自动扫描和 HTTP 启动请求均不产生无消费方的订阅。
- SSE 活动状态包含 `pending` 与 `running`，连接收到终态或通道关闭时结束；每 15 秒发送注释心跳检测空闲断连，写入或刷新失败立即退出并释放订阅、停止心跳计时。连接释放不取消扫描，也不影响其他订阅。
- 终态与活动任务统一从同一个订阅快照推送，避免读取状态后再订阅的竞态；重连保持原始阶段、进度、耗时、数量和媒体库 revision，不重新拼装缺失字段的事件。
- `DELETE /api/scans/:id` 取消 context；取消结果不发布到库缓存。
- 终态任务短期保留供重连查询，随后自动回收。
- SSE 中的 `currentPath` 只使用根别名和相对路径。

扫描器保留目录层级：纯媒体目录形成相册；同时包含媒体和子目录时形成集合，并以“本目录媒体”虚拟相册表示当前层媒体。虚拟相册与集合共享真实物理目录，由资源 kind 生成不同 ID，不再使用不存在的 `.loose` 路径。文件和目录均使用自然排序；普通子目录不可读、元数据失败和符号链接以脱敏告警返回，根目录失效则整轮失败。

虚拟相册的 `name` 恒为“本目录媒体”，只是类型标记而非展示名：扫描时另外写入 `location`（归属目录相对媒体根的斜杠路径，根目录自身用根名），由摘要透传到前端做卡片标题与搜索命中。相对路径而非 basename，是因为不同父目录下可能有同名目录，只有完整路径能唯一标识；`location` 随扫描结果落盘，因此扫描缓存 schema 随该字段一并升版。

时间轴只消费扫描层产出的 `date`，不在前端重复解析名称。日期解析器保留 `captured > folder > modified` 的固定优先级；首轮快速扫描不遍历读取所有 EXIF，避免百万媒体库产生大量随机 I/O，未有拍摄时间时使用严格目录日期或媒体修改时间。

列表的“最近改”排序统一使用摘要 `modTime` 倒序，卡片映射保留修改时间；缺失或无效时间排在末尾，同时间按名称稳定排序。主页、集合、收藏、最近、未读与标签共用时间比较逻辑，业务日期继续用于时间轴分组。

## 媒体管线

缩略图请求在配置读锁内完成缓存查找及生成，配置热更新和清空缓存使用写锁。尺寸和编码版本参与派生缓存键，HTTP ETag 基于实际 JPEG 字节。图片解码的并行度上限为 `min(12, NumCPU)` 个任务，并受 192 百万像素的并发像素预算约束（见下文性能对照）；视频封面最多两个任务，同一文件通过 singleflight 去重。原图、视频与缩略图使用 `private, no-cache`，允许缓存但要求重新验证。原图和视频共用 `mediaNotModified`，在条件判断前设置策略、ETag 与 Last-Modified；优先处理 If-None-Match，仅缺省时按秒处理 If-Modified-Since。

纯 Go 解码器不支持的图片格式（iPhone 的 HEIC/HEIF）由可选的 ffmpeg 转换器兜底：先用 `-filter_complex` + `-map` 解码缩放（HEIF 码流由多帧组成，ffmpeg 视其为复杂滤镜图，用 `-vf` 会直接报错），再走与纯 Go 路径相同的缩放与编码，输出尺寸与质量完全一致。ffmpeg 不可用或转换失败时返回 415，前端显示占位图而不是浏览器的破图图标。

服务端视频封面由可选的 ffmpeg 抽帧：`-ss` 放在 `-i` 之前做快速定位，等比缩放后以 image2pipe 直接输出 JPEG 字节。定位点必须落在视频流之内：时长按视频流读取而不是容器时长（容器时长会被更长的音轨拉长），定位点越过画面末尾时 ffmpeg 一帧都解不出来。这类短视频（片段本身短于 1 秒）改取片头帧；首次抽帧没有输出时也用片头帧重试一次。ffmpeg 不可用时维持浏览器抽帧回退。

抽帧只缩小不放大、且**不补边**：封面保留视频帧的原始宽高比，与图片缩略图（`imaging.Fit` 等比缩放）以及浏览器抽帧回退（`SaveVideoCover` 同样等比缩放）保持一致。早期实现用 letterbox 把画面补黑边到固定尺寸，16:9 视频因此近一半像素是死黑，而且同一个视频会因为封面由哪条路径生成而形状不同。网格是竖框（3:4）而视频帧通常是横的，所以前端用 `object-contain` 展示视频封面：按 `object-cover` 填满竖框会把画面裁掉一大半，只剩中间一条。封面缓存键带 `vc2:` 版本号前缀，形状规则变更后旧缓存自动失效并重新生成。

三类媒体共用 `mediaIfNoneMatch`，按弱比较处理单个 ETag、列表和独立通配符；重复字段行先合并。解析按引号边界读取标识，保留内部逗号及反斜杠字面值，接受列表空项，格式错误则不命中。304 保留当前验证标识与缓存策略，不发送媒体字节或 Content-Range。源类型、路径及缩略图实际内容检查仍先于缓存条件；If-Range 继续独立使用强 ETag 或精确修改时间。

原图与视频由 `serveMediaFile` 共用流式发送：在路径校验及可选视频管线之后打开最终文件，以同一次 `f.Stat` 的普通文件类型、大小及修改时间生成响应头和 ETag，不使用静态文件服务的句柄缓存。范围解析复用 fasthttp，补充拒绝空后缀等无效结果；完整响应直接复制文件流，局部响应用 SectionReader 限定读取区间，均交由 Fiber 在完成或断连时关闭。HEAD 不发送媒体字节，304 与发送前错误在返回前关闭文件，不产生保留文件句柄的后台任务，也不读取整段媒体到内存。读取、复制和关闭错误去除 PathError 中的本地路径；416 返回统一 JSON 与当前总长度。打开后的外部原地写入仍不构成文件系统事务隔离。

常规缓存条件之后、范围解析之前，`mediaRangeMatches` 使用同一次打开的文件信息校验 If-Range。缺省标识、相等的强 ETag 或精确到秒相同的 HTTP 日期允许读取片段；其余值忽略 Range，发送完整当前文件，避免源文件更新后将新旧版本拼接。旧标识携带越界范围也不进入 416 分支。

浏览器抽帧回退通过媒体 URL 和浏览器原生 Range 请求按需读取，不先下载整段视频为 Blob。抽取 JPEG 后立即移除视频源并重置媒体元素、释放 canvas；短视频的定位点保持在片尾之前，未知时长等待第 0 帧数据可解码。上传完成后重新探测封面，沿用稳定 URL 交由 HTTP 缓存头验证。

HTTP 重新验证不能保证同页媒体解码缓冲被丢弃。视频 URL 因此带客户端生成的随机 `playback` 标识：播放器按资源 ID 与重试代次 memo 化 URL，普通父组件重绘保持地址不变，切换及返回同视频、手动重试和转码完成产生新地址；每次抽帧也独立生成地址。随机值通过 `crypto.getRandomValues` 生成，不依赖安全上下文限定的 UUID 方法，支持当前 LAN HTTP 部署。标识只作为浏览器缓存分隔，不参与后端任务键或鉴权，不写入持久活动。新的尝试重新读取所需片段，同次播放继续使用原生 Range。

每个资源/重试由一个组件 effect 拥有完整的探测、抽帧与上传任务。切换资源、重试和卸载时取消整条任务，迟到结果不能上传或改写新资源状态。HEAD 只有 404 进入短轮询，网络异常和其他 HTTP 失败立即进入可重试错误态；20 秒探测期限包含挂起请求，超时后进入浏览器抽帧回退。抽帧自身另有 30 秒期限，成功、失败、取消和超时均清理媒体事件、网络读取及计时器。

缩略图并发改用两道闸门：并行度上限跟随 CPU 核数（`min(12, NumCPU)`），同时用像素预算（192 百万像素）限制并发解码的像素总量。像素预算是比"并发张数"更准确的内存单位——大图自然只能少量并行，小图（截图等）可以跑满并行度而不撑爆内存；核数较少的机器上并行度与旧实现一致。权重取自图片头（`image.DecodeConfig`，不解码像素），读不到头部时按大图保守处理。

大原图（手机常见的 12MP 以上）不再直接跑 Lanczos：先用一个廉价的 Box 面积平均把长边压到目标的 2 倍以内，再在小图上做 Lanczos。这是 libvips / ImageMagick 的标准降采样做法，结果与直接 Lanczos 肉眼无差别（单元测试以平均像素误差 < 3/255 约束），耗时降到零头。

图片通过 `/api/media/:fileId` 发送，使用 mtime + size 生成 ETag。缩略图采用内存 LRU 和磁盘缓存，源文件变化时失效。

视频单条与批量信息共用响应构建器，使用同样的文件 ID 与父目录语义，读取前区分目录资源、非视频及失效文件，文件被同名目录替换时按不存在处理。单条查询复用资源参数中间件固定的快照，批量查询在请求内固定一次快照并保持输入顺序及逐项错误；探测不可用时继续返回基础文件信息。

`VideoInfoService` 将成功摘要按规范化路径、文件大小和纳秒修改时间放入最多 512 项的内存 LRU，API 与转码判断复用同一服务。每次查询先检查当前文件指纹，命中时返回值副本；同一指纹的并发未命中通过 singleflight 合并，失败不缓存，探测期间文件变化不回填结果。缓存仅存元数据，不保存媒体字节，也不会代替 HTTP 层的实时路径校验。指纹不区分大小及修改时间均被保留的内容覆盖，这种情况可使用一键全清强制重探测。

`scope=all` 同时清空视频摘要并推进缓存代次，清空前启动的探测仍可完成，但不能回填新缓存；清空后的请求也不会加入旧代次的探测。摘要不持久化，不参与派生磁盘占用与删除计数。

批量视频信息显式接收与资源参数中间件共用的 `PathValidator`，逐项复核当前媒体根与链接状态，再使用校验返回的路径读取文件信息及探测。扫描快照负责稳定的资源元数据，不作为当前路径仍然安全的证据；校验器缺失时拒绝请求。

视频发送顺序：

```text
浏览器请求
  → 已缓存的按需转码
  → MP4 faststart remux
  → 原始视频
```

元数据优先读取 ffprobe JSON，缺失或失败时解析 `ffmpeg -hide_banner -i` 的输出；可用性由任一工具能成功执行版本检查决定，版本检查与文件探测均有超时。文本回退只读取输入头、时长行和首个视频流，忽略同名元数据标签，保留完整容器别名列表并读取尺寸、编码、码率；数字字段过滤非有限值。未指定输出时 ffmpeg 的正常非零退出仍可提供有效字段，超时或启动失败则拒绝部分输出，不写入成功缓存。

浏览器不支持的编码按需转为 H.264 + AAC，转码判断复用相同元数据服务；MP4 的 moov atom 不在前部时仅 remux。转码按同版本任务去重并使用全局并发限制，SSE 订阅断开时释放订阅资源。ffmpeg 不可用时能力降级而不阻断图片和原生可播放视频。

faststart 与转码共用缓存条目校验：使用 `Lstat`，仅非空普通文件可命中，拒绝条目自身的链接、目录和空文件。转码完成任务与重启后的磁盘缓存状态使用同一规则；媒体 handler 在选择派生文件后再次复核，并用该文件的元数据生成 ETag，复核失败则继续后续管线。检查不解析视频内容，也不提供外部文件系统改写的事务隔离。

两类生成均在目标目录创建独占临时文件，ffmpeg 成功退出且输出通过条目校验后才原子重命名为最终哈希路径，避免 faststart 直接写最终文件留下可命中的半成品。失败只清理本次临时文件，不删除最终路径上的目录或其他条目，也不复用旧固定临时路径。空缓存可按需重建；目录占位导致发布失败时，转码状态为 `failed`，播放请求继续 faststart 或原文件回退，faststart 失败日志不输出本地路径。

转码任务记录不可变的派生产物路径，其键包含源路径、大小、纳秒修改时间与 profile 名称。复用与占位在同一个服务锁内完成，仅同版本活动任务可以复用；替换任务及取消不同版本任务时在锁内核对源指纹，避免携带旧 `Stat` 的迟到请求反向取消新任务。新媒体请求观察到版本变化时取消旧任务，即使新版本已命中缓存或无需转码也会取消。被替换任务保留在待回收集合，后续启动剔除已结束项，`Shutdown` 取消并等待当前与旧版本任务，避免仅等待最新路径记录而遗漏旧 worker。转码执行前和原子发布前比较当前源大小、修改时间与普通文件类型，变化时只清理本次临时输出并返回 `video source changed`；大小和修改时间均被保留的内容覆盖不在此指纹检测范围内。

查询与订阅共用 `currentState`：先确认当前版本的已发布缓存，再读取同版本任务；旧进度或失败不遮蔽有效缓存，不再维护无读取用途的 `cached` 集合。订阅仅对当前版本的 `queued` / `running` 任务保留订阅者，在服务锁中确认任务仍为当前记录，再在任务锁内注册并发送初始快照；任务刚结束或已被替换时重新取状态，其余状态发送一次完整快照并关闭通道。探测与磁盘检查在锁外完成。进度发送、终态发送与通道关闭、取消订阅都由同一任务锁串行保护；慢订阅者可丢弃旧进度，但终态保留，取消可重复执行且不影响其他订阅者。HTTP 层仅对活动状态发送 `progress`，其余状态发送带完整数据的 `done` 后断开，不生成空终态或为已完成任务保留订阅。

## 配置与持久化

偏好部分更新在 store 的同一写锁中完成读取、字段修改和原子落盘，避免修改主题时覆盖并发新增的收藏或历史。返回值是归一化后的已提交快照。

资源请求通过 `pathutil.MostSpecificRoot` 选择最具体的已配置根，与资源 ID 的归属及 SSE 路径标签保持一致；根顺序不影响授权。根本身是显式配置的授权边界，可以是目录链接；其内部未单独配置的符号链接和 Windows junction 仍逐级拒绝，包括扫描后才发生的目录替换，失败不回退到更宽泛的父根。原子根状态复用共用规范化规则，空白项不会授权进程 CWD；不再维护未参与判定的路径前缀副本。该检查不将本机可任意并发改写文件系统的进程视为隔离边界；媒体目录应由受信本机程序管理。

文件资源 ID 只固定扫描时的身份，不保证当前路径仍是文件。原图和视频响应复用现有 `Stat` 检查 `Mode().IsRegular()`，先于 ETag、Range、转码选择与文件发送，避免目录进入 Fiber 文件服务并在重定向头中暴露本地路径。图片信息服务以 `ErrSourceMissing` 表示源类型失效，视频单条/批量元数据同样拒绝非普通文件；缩略图查询及封面上传在访问缓存、解码或写盘前复核源类型，统一按源失效返回 404。该校验不修改已发布目录 revision，恢复普通文件后原 ID 自动恢复读取。

扫描时先按配置根 key 判断委派，再判断符号链接与 `ModeIrregular` 条目。显式链接根由自身独立扫描，父根不重复收录或告警；其他链接使用 `symlink_skipped` 告警并跳过，避免 Windows junction 被扩展名分类器误当作媒体文件。

`POST /api/fs/open` 的请求体资源 ID 由 handler 解析，再使用与资源路由共用的 `PathValidator` 按当前媒体根校验；扫描快照和 `allowConfig` 查询参数均不能替代此步骤。调用系统打开器前，还确认路径存在且目录/普通文件类型与资源快照相符，失效统一返回 `resource_not_found`。系统打开器由启动入口注入，使资源解析、路径校验和桌面副作用分离；单元与集成测试使用记录器确认未通过校验的路径不会进入系统调用。

- 配置：`backend/config.yaml`，`mediaRoots` 是唯一媒体根字段。
- `pathutil.NormalizeRoots` 相对进程 CWD 绝对化、去空并保序去重；`RootKey` 与根资源 ID 共用 Windows 忽略大小写、其他平台区分大小写的规则。规范化不读取目录，不解析链接；离线根仍能参与配置和缓存比较。读取配置、写回 YAML、扫描进度根数、资源根索引和 `mediaRootsChanged` 使用同一规则，避免等价路径重复扫描或触发清库。
- 默认工作目录：进程 CWD 下 `.local-gallery/`。启动时只创建当前分层布局；旧顶层文件不会被读取、移动或删除。
- 持久状态：`state/scan_cache.json`、`state/web_settings.json`、`state/activity.json`、`state/cover_overrides.json`；任何缓存清理接口都不得进入 `state/`。
- 派生缓存：`derived/thumbnails/`、`derived/converted/`、`derived/video-faststart/`、`derived/video-transcode/`；按内容派生键写入，可安全重建。`derived/converted/` 存 HEIC/HEIF/TIFF 的整图转换产物，单张可达 MB 级，因此在缓存占用统计与清空接口（scope=converted）里都单独成类，不与缩略图混算。
- 临时文件：统一写入 `temp/`，不与状态和派生缓存混放。

`host`、`port`、`staticDir`、`cacheDir` 和 `ffmpegPath` 属于启动期资源，修改后重启。扫描根、扫描排除规则、缩略图尺寸/LRU/保留天数和 `allowOsOpen` 可热更新。

进程收到 `SIGINT` / `SIGTERM` 后先停止接收新连接，同时取消活动扫描和视频转码；退出前强制刷新扫描快照。HTTP 连接最多等待 5 秒，后台任务与缓存清理共用 10 秒退出窗口。

## 前端状态边界

- TanStack Query 管理 library、album、metadata、prefs 等服务端状态和失效。
- Zustand 管理主题、筛选、画廊模式、键盘交互等客户端状态。
- URL 保存可分享的导航状态，只包含资源 ID；阅读器统一使用 `/gallery?path=<albumId>&index=<n>`，标签使用 `/tags/<tag>` 路由。
- 全部业务页面按路由懒加载，应用外壳保持常驻；首页 Hero 等大页面区块按领域组件和 hooks 拆分。
- `AlbumGrid` 的网格和列表通过 `customScrollParent` 绑定最近的纵向滚动祖先：普通页面使用主内容区，集合页使用集合内层滚动区；尚未生成列表占位高度时也先绑定容器，独立挂载且没有滚动祖先时使用窗口。相册详情的图片/视频/混合媒体网格使用各自填满内容区的滚动容器。所有列表只挂载视口附近的卡片；筛选与跨卷上下文仍保留完整的轻量摘要数组，不复制到长期 store。
- 视频和混合媒体缩略图将封面层与打开/播放按钮分离；封面重试按钮独立于播放按钮，并位于其点击层上方，避免嵌套交互元素和键盘重试误打开播放器。
- 相册媒体网格保留总长度占位，共用 `useMediaGridPagination` 按视口末端与已加载数量预取，不能依赖整本相册的 `endReached`。页面追加后重新检查当前范围，使远距离跳转能连续补页；分页失败暂停自动取页，保留已加载内容并提供显式重试，重复触发不会取消活动请求。
- 图像库快照按任意深度集合递归构建 ID 索引；常驻导航通过随机相册和阅读摘要接口获取单项/计数，首页通过仪表盘接口获取未读计数、有限预览和在读摘要，均避免下载全量相册。未读计数、首页预览、随机未读与完整未读分页共用服务端按“目录 revision + 活动版本”派生的下标索引；同一版本不会重复扫描全库，最近、收藏等列表仍按页面需要查询摘要。
- 扫描 SSE 终态保留到用户显式重置，路由切换不会丢失完成/失败结果。活动模型同时承载 0-based 图片页码和毫秒视频位置，但使用不同复合键；图片到达最后一页、视频到达 98% 时由服务端派生完成状态。

阅读器的视频播放位置由 `useVideoActivity` 单独承载：它把「恢复查询 → 节流写入 → 卸载补写」这条链连同 pending/writable/blocked 阶段机收在一个 hook 里，路由组件只拿「从第几秒开始播」和「把进度交给我」两件事。恢复查询返回前不写任何位置，否则自动播放产生的 timeupdate 会覆盖用户已有的恢复点；四个回调经 ref 转发，调用方传内联箭头函数也不会让恢复查询反复重启。视频位置与图片页码是两套模型，互不覆盖。

扫描前端将连接状态与任务状态分开保存。原生 EventSource 错误只更新连接状态，业务 `error` 消息才确认扫描失败；断线保留最后一次有效进度，显示结果待确认并继续禁止重复启动。浏览器自动重连收到有效快照后恢复显示，关闭的连接可由用户通过“重新连接进度”重新订阅同一任务，仅发送 GET，不发送启动扫描的 POST。进度卡可折叠，连接中断与终态确认前持续保留重连入口；Ctrl+S 与扫描按钮采用相同的活动任务保护。连接无法恢复时，“停止跟踪”只清除前端当前任务并释放连接，不发送取消或启动请求，后台扫描继续按原流程运行。

SSE 封装只将 MessageEvent 交给业务回调，JSON 解析与消费回调分开，消费异常不会造成原始文本的重复分发。取消时关闭连接并移除所有事件和 AbortSignal 监听，排队消息也忽略；扫描订阅同时检查连接所有权、任务 ID 与负载字段，避免迟到或畸形消息污染当前任务。订阅跟随共享任务而非路由组件，页面切换保留连接和恢复状态。

前端不得把服务端快照再复制成第二份长期 store。写操作成功后以查询失效或精确的乐观更新同步，避免双数据源漂移。

相册详情记录访问时只依赖资源 ID、名称和图片总数，不依赖随媒体分页重建的详情对象。相册详情、阅读器和设置页通过共享助手同步已确认的历史快照到 `history` 与已有 `prefs.history` 缓存，再异步刷新，确保最近阅读、首页和收藏的“最近看”排序立即采用操作结果，读取失败不会复活已清空的记录。调整保留条数采用偏好响应中服务端已裁剪的历史，其他偏好写入不覆盖历史查询缓存。

主页、集合、标签、收藏和未读页通过 `useViewedSort` 复用同一份历史查询与时间比较器，仅在选择“最近看”且列表含相册时请求历史；最近页通过 `useHistory` 始终读取作为页面数据源的历史。“最近看”按 `openedAt` 倒序，未访问项置后，同时间按名称排序。集合与智能视图自身没有相册访问记录，按名称兜底。排序依赖首次加载时保留卡片并提示加载，读取失败提供重试；已有历史缓存时继续采用缓存顺序，没有缓存时暂按名称排序，切换其他排序即移除该提示。集合和标签页复用 `ListFilterBar` 提供当前页排序与视图切换。首页也复用它，但放在「全部图像」网格正上方而不是页面顶部：它只过滤这一张网格，页面前半段是未读 / 继续阅读 / 时间线三个区块，控件提到那里就离网格两千多像素，用户滚到网格时控件早已不在视野内。

排序选项使用触发按钮之后的原生按钮组，保留页面 Tab 顺序，并通过展开状态、控件关联和按下状态公开当前选择。确认排序或按 Esc 关闭时恢复触发按钮焦点，焦点移出或点击外部时只收起选项。外部点击监听在展开时直接注册，在关闭及卸载时移除，不留下延迟注册任务。

未读摘要不构造阅读进度；有图片的相册没有图片活动表示未读，纯视频相册没有图片活动可依，改以视频播放活动表示已翻开，单图相册只有真实保存第 0 页活动后才算读完。`AlbumContextMenu` 统一网格、列表和独立卡片的阅读标记与常规操作，列表容器持有菜单时卡片只转交事件，避免两份菜单叠加。标记能力和目标末页由当前图片总数决定，不依赖已有进度；纯视频和聚合卡片不提供图片阅读标记。操作依赖只在菜单展开时订阅，标记和重置共用活动 mutation，成功后刷新单项与批量活动缓存；菜单卸载后仍反馈写入结果，失败保留原状态并允许重试。

`App` 常驻的 `useLibraryActivitySync` 监听活动写入成功事件，统一失效阅读计数、首页仪表盘和完整未读列表的缓存。只有已挂载的查询立即重新获取数据，其他页面的缓存标记失效，返回时再读取；因此在收藏页取消已读或从独立画廊返回后，不会继续使用尚在 30 秒有效期内的旧未读结果。页面查询只负责读取，不随挂载和卸载分别注册同步监听。

卡片右上角的星标直接写收藏：星标与卡片链接平级，`<a>` 内嵌按钮会让 Enter 冒泡触发跳转，也会污染可访问名。网格把星标和视频角标放进封面右上角的浮层，列表把星标放在行尾，`AlbumCard` 通过 `overlayAction` 让首页未读预览的「标记为已读」共用同一浮层，避免两个按钮抢占同一个角。桌面端悬停卡片才显示未收藏的星标，已收藏的常驻显示；窄屏没有 hover，星标常驻。星标与右键菜单共用 `favoriteResourceId` 计算资源 ID，写入失败给出中文提示而不是静默失败。星标只写不订阅收藏列表（`useToggleFavorite`），避免上百张卡片因一次收藏写入全部重渲染。

属性弹窗通过 `PropertiesTarget.kind` 区分库节点与图片文件：相册、集合使用节点摘要查询显示名称、来源、扫描统计、大小和修改时间；图片使用文件 ID 查询元数据，展示格式、尺寸及校验和等字段。菜单不再把相册 ID 传入图片接口，标签聚合卡片不提供目录属性。两类查询都支持失败重试，节点失效显示不可用提示，切换文件会清除旧图片字段并忽略过期响应。

`PropertiesDialog` 使用原生模态 dialog 隔离背景交互，并在首尾按钮间处理 Tab 循环；键盘事件不会触发背景页面快捷键。右键菜单记录并恢复来源焦点，弹窗关闭后再回到来源；重试期间将焦点保留在关闭按钮。目录属性标明来自最近一次扫描，不额外遍历用户目录。

`HelpOverlay` 同样通过原生模态 dialog 隔离背景，标题与搜索框提供可访问名称。打开时先记录来源再聚焦搜索，Tab 在可见输入和按钮间循环；键盘及右键事件不冒泡到背景阅读器。Esc 走原生 cancel 事件关闭受控浮层，关闭按钮和遮罩共用关闭入口，清理时恢复仍存在的来源焦点。模态生命周期只依赖 `open`，父组件进度更新或回调重建不重新打开弹窗、抢回焦点；清除搜索主动聚焦输入框，避免清除按钮卸载后丢失焦点。

帮助内容使用 `SHORTCUTS` 中的 `global`、`reader`、`image`、`video` 分组。`AppShell` 显式传入 `library` 场景，`Gallery` 从当前媒体类型传入 `image` 或 `video`；帮助只选择主页面分组，或阅读器共用与对应媒体分组，再匹配搜索词。视频播放、音量、静音及换片与图片显示操作独立声明，封面和帮助别名列在阅读器共用组。只有一组结果时铺满内容宽度，空结果跨完整网格；不复制场景到持久 store，也不改动按键注册逻辑。

`Popover` 与 `ContextMenu` 共用 `handleMenuKeyDown`，在菜单根节点隔离背景按键，使用当前可用项处理上下循环和 Home/End，Esc 由菜单直接关闭，不再注册全局 Esc 监听。空格和回车沿用按钮原生激活；已取消、输入法和 Ctrl/Alt/Meta 组合不执行菜单导航。无可用项时聚焦带负 tabindex 的菜单容器，焦点离开则关闭。`Popover` 保留已打开菜单的元素引用，关闭时只在焦点仍属于菜单或回到 body 时恢复来源，避免 Tab 或外部点击后抢回焦点；右键菜单沿用同样的恢复边界。

工具栏 `ThemeSwitcher` 复用 `Popover` 的定位、开关、焦点和按键隔离，不再自行延迟注册全局监听。定位与焦点转移在布局阶段完成，避免快速打开后按 Esc 时事件仍落在触发按钮；主题面板只做透明度淡入，保留定位所需的水平变换。主题与强调色各自使用具名分组及 `menuitemradio` / `aria-checked` 表示互斥选择，选择后保留菜单以便连续调整。`Popover` 的初始焦点与方向键导航使用同一个可用项选择器，同时支持普通操作项和单选项，并排除原生或 ARIA 禁用项。强调色名称和预览色复用 `ACCENT_SWATCHES`，不保留独立调色板。

`utils/clipboard.ts` 为属性字段和卡片菜单统一复制能力：优先调用剪贴板 API，不可用或被拒绝时在所属已打开的 dialog 内创建临时文本选区，无弹窗时使用页面 body；只有成功聚焦并选择文本后才执行复制，结束时始终移除临时元素，并恢复先前焦点。来源元素已卸载时改用当前焦点确定选区容器；调用方可在异步权限检查后禁止过期操作继续回退。

`CopyButton` 等待期间合并重复点击，公开忙碌状态并保持可聚焦；失败显示可重试提示。成功反馈从最后一次复制起保留 1.5 秒，切换文本或卸载时清理计时器并忽略过期异步结果，避免关闭弹窗后再次回退或弹出错误。卡片右键的“复制链接”通过 `useAlbumActions.copyLink` 复制当前站点的完整相册、集合或标签地址，保留路由中的百分号编码；菜单关闭后仍完成复制并反馈结果，用户可重新打开菜单重试。相册详情的“更多”和图片右键复用同一动作，图片菜单明确标为“复制相册链接”。

`useFsCapabilities` 通过共享 Query 缓存订阅系统文件管理器权限，未知状态保持关闭，健康检查结果可在菜单已打开时更新按钮。确认读取配置或保存 `allowOsOpen` 后直接发布该权限并取消旧健康检查，避免迟到响应回退设置；保存配置前也取消尚未完成的旧配置读取。相册、集合操作只向资源接口提交 ID，设置中的媒体根、缓存和前端目录统一走配置路径白名单接口。系统打开请求不自动重试，配置目录的 GET 也不缓存结果，避免重复启动系统操作。菜单关闭后仍提示操作结果，业务错误映射为中文提示，原始响应和绝对路径不进入通知状态；本机接口拒绝远程请求时明确提示用户在运行服务的计算机上操作。

最近阅读分别处理历史查询与相册摘要查询状态，只有成功取得空历史才显示没有记录；失败提供显式重试并保留已加载卡片。摘要成功但资源均失效时显示相册暂不可用，不误导用户清除筛选。

收藏 Hook 暴露列表查询状态，收藏页分别处理列表、相册摘要和标签摘要的加载失败，只重试失败的查询并保留已解析卡片。确认列表为空才显示没有收藏，资源均失效与筛选无结果使用不同提示；访问历史仅在“最近看”排序下查询，排序依赖失败不隐藏收藏。

收藏增删成功后先把服务端完整响应写入共享查询缓存，再异步刷新，不让后续读取失败覆盖已确认的状态或拖延成功反馈。切换收藏通过 QueryClient 获取当前列表，避免旧回调捕获过期数组；首次读取未完成时复用同一查询等待结果，无法确认状态时不发起切换写入。

失效收藏清理成功后，用返回的移除 ID 清单过滤已有收藏和偏好缓存，再刷新列表，项数不会在读取失败时回退。没有收藏查询缓存时不凭移除清单构造空列表，后续仍由完整查询确认；清理失败保持原缓存。

设置页区分偏好首次加载与读取失败，失败提供重试并保留已有设置。阅读设置写入成功先用服务端完整响应更新查询缓存，再刷新；后续读取失败仍保留已确认的新值。保存阅读设置、清理失效收藏和清空历史均提供失败反馈，执行期间禁用相关按钮，阅读设置的不同字段也不交错提交。

服务端配置的字段状态使用函数式合并，成功提示按字段独立计时 1.5 秒；同一字段再次保存时取消旧计时，面板卸载时取消全部提示定时器。卸载后返回的写入结果继续更新共享配置与库缓存，不再更新页面状态或创建提示定时器。

阅读器标题与最近访问记录共用已查询的相册摘要；URL 名称仅在摘要未就绪时提供显示提示，不作为持久化元数据。媒体和相册摘要均可用后才记录访问，图片总数保持相册语义，纯视频相册记录为零，不使用当前视频数量替代。

阅读器按媒体类型注册快捷键：图片的左右翻页、空格幻灯片及显示变换只在图片模式生效；视频的左右定位和空格播放由 `VideoPlayer` 独立处理，Gallery 通过 PageUp/PageDown、Home/End 操作 URL 中的视频序号。视频首尾定位先判断媒体类型，计数与换片按钮提示也不读取图片显示模式。视频模式暂停图片幻灯片计时；Esc 依据当前媒体是否就绪返回，不再依赖图片数组判断视频可否退出。

`useKeyboard`、`VideoPlayer` 和 `PageSlider` 共用 `shouldIgnoreShortcut`：先排除已取消和输入法组合事件，再通过元素祖先识别输入、选择与可编辑区域；空格和回车留给按钮、链接及折叠摘要，包含 SVG 等子节点。页面处理器调用 `preventDefault` 后，同一事件不再触发另一份快捷键。通用 Hook 仍按规范化组合匹配显式注册项；视频和页码的独立监听另外排除 Ctrl / Alt / Meta，保留浏览器与系统组合行为。

## 安全与生命周期

- 默认监听 `127.0.0.1`；管理端点额外校验回环地址。
- 所有路径拼接使用 `path/filepath`，解析后再次校验根目录边界。
- 公共错误返回稳定 code/message，不回传底层含路径错误。
- 后台任务、定时器和 SSE 订阅均有明确 owner、取消函数和回收时点。
- 扫描快照对 Get/Set 都做深拷贝；并发落盘按版本确认，清空操作与写盘互斥，避免旧快照复活或覆盖新结果。

## 测试边界

- Go 单元测试覆盖 service、middleware 和 handler 行为。
- `tests/integration` 使用真实 Fiber 路由验证扫描、资源 ID、缩略图与 SSE 主链路。
- Vitest + Testing Library 覆盖前端查询、store、hook 和组件行为。
- Playwright 从临时媒体根启动完整应用，验证首屏扫描、资源 ID 媒体访问、三类媒体网格跨页和分页失败恢复；分页素材超过两页，封面与视频元数据用小响应隔离 ffmpeg 依赖。

标准验证命令见根 README。性能优化扫描或缩略图主路径时，另记录样本规模、吞吐、p95 和内存前后对照。

### 阅读进度失败恢复

阅读器的图片与视频活动查询失败时暂停保存，并显示持续提示；用户重试成功后再开放写入。页面内的保存失败显示重试按钮，重试读取当前有效页码或视频播放位置，成功后清除提示。切换资源后不展示上一资源的延迟失败。页面卸载的 keepalive 仍属尽力写入，浏览器关闭后的响应不作为已保存确认。

主题监听和 Toast 通知由应用层统一挂载，包含独立阅读器与解锁页；设置页和普通页面布局不再重复注册监听。

主题颜色仍由 `tokens.css` 统一定义，Tailwind 通过带 `<alpha-value>` 的 `color-mix` 映射支持透明度修饰符，并显式注册细边框令牌。错误提示、半透明背景及边框随明暗模式和强调色切换，不依赖浏览器默认边框色；浏览器回归检查实际渲染的颜色与透明度。

### 前端样式约定

自定义类写在 `styles/global.css` 的 `@layer components` 内。未分层的自定义规则会压过 Tailwind 工具类，例如 `.kbd` 会盖掉 `hidden sm:inline-flex`，使窄屏下的快捷键提示无法隐藏。

窄屏（< 640px）按"页面不出现横向滚动"收敛：顶栏搜索框必须允许收缩（`min-w-0`），共享筛选条的视图标签独占一行且文字不折行。设置项（标签 + 控件）在窄屏改为上下堆叠，否则路径输入框会把中文标签挤成一列竖排文字。Playwright 以 390px 视口回归这三点。

支持的媒体格式只有一份白名单（`models.ImageExts` / `models.VideoExts`），扫描器、封面类型判定与"设为封面"校验都走 `models.FileMediaKind`，避免各处复制清单后漂移。浏览器放不了的容器（MKV / AVI / 3GP）一律转码，不按码流判断——H.264 装在 MKV 里 Chrome 同样放不了。

HEIC/HEIF/TIFF 浏览器原生解不了，原样发送只会让阅读器显示破图。服务端在 `GET /api/media/:id` 上先用 ffmpeg 转成 JPEG（最长边 2560）再返回，ETag 仍取源文件的 mtime+size，条件请求照常协商 304。转换结果按源文件 mtime+size 派生的键缓存在 `derived/converted/`，与缩略图缓存分开存放（单张可达 MB 级，共用同一个内存 LRU 会把缩略图挤掉）。没有 ffmpeg 或转换失败时返回 415，前端显示"该图片无法显示"而不是破图图标。

入口与页面都有兜底：`AccessGate` 的会话检查带 15 秒超时（后端无响应时进入可重试的离线提示，而不是一直停在「正在确认访问权限…」）；`/gallery` 阅读器不挂在 AppShell 下，因此路由层再包一层 `ErrorBoundary`，阅读器渲染异常时给出提示与重试按钮，而不是整页空白。

阅读器的显示设置（模式 / 适配 / 缩放 / 旋转 / 方向）在桌面端是右侧悬浮控件，在窄屏会盖住图片右缘并挡住"点击右侧翻下一张"的热区，因此 `GalleryControls` 的悬浮列只在 `md` 以上显示，窄屏改由顶栏的「阅读设置」弹层（`GalleryDisplayMenu`）提供同一组操作；翻页按钮本就在窄屏隐藏，那一列在窄屏只剩空面板。

阅读器连续模式按容器宽度展示图片，因此改用服务端按宽度缩放的预览图（`GET /api/previews/:id?w=`），而不是原图：手机照片动辄 5MB+，直接发原图时翻一本相册就是 GB 级流量，浏览器还要为每张原图解码出几十 MB 位图。预览图按源文件版本与目标宽度分别缓存到 `derived/previews/`，可在设置页单独清理。单张与并排模式仍用原图——缩放和"原始"适配需要完整分辨率。连续模式的虚拟列表另外用 `minOverscanItemCount` 保证视口前后各挂一张，`overscan` 在 `Virtuoso` 里是像素而不是"张数"，写成 3 等于没有预渲染，滚动时每一步都要等图片下载完才出图。

阅读器画布恒为深色（`bg-neutral-950`），顶栏与浮层控件都按"深色底"渲染，不跟随应用主题；加载态、空态、加载失败态与"进度未保存"提示同样按深色渲染——否则浅色主题下会先闪一屏白底再跳到黑色画布，或在黑底画布里嵌一块白板。图片信息面板（`ImageInfoPanel`）同样遵守这一约定：早先它用主题色（`glass` + `border-border-faint`），在浅色主题下会变成"黑底阅读器里嵌一块白板"，并且面板作为普通块级元素排在画布之后，直接压在顶栏上、盖住返回按钮。现在阅读器根节点改为横向 flex：画布与控件收进一个 `flex-1 min-w-0` 的舞台列，面板在 `md` 以上作为独立的一栏（`md:static md:w-72 md:shrink-0`）与画布并排，窄屏则改为顶栏下方的整宽浮层（`top-11` 让开顶栏）。面板宽度会改变画布宽度，连续模式下的"可见区末页"随之变化，因此关闭面板的判据是当前媒体的资源 ID（`currentMediaId`）而不是页码，否则面板一打开就会被自己关掉。Playwright 回归"面板不遮挡顶栏"这一点（宽屏并排、窄屏落在顶栏下方）。

### 离线媒体目录的降级

运行参数校验与媒体目录可用性分离。目录离线时继续提供设置页；显式修改根配置时检查实际目录，其他设置可独立保存。扫描维持整批提交：任何根不可用时不发布部分结果，保留旧快照以及用户状态。首页空状态提供设置入口。YAML 语法、访问令牌和端口等运行参数错误仍阻止启动。
