## R0 · 基线重建（2026-11-03）

### 背景

上一轮（见 [UI_REDESIGN.md](./UI_REDESIGN.md)）把界面从"后台"往"画廊"拉了一大截，
`docs/UI_ACCEPTANCE.md` 里 A1–A7、B1–B8 全绿。**但历史验收通过 ≠ 当前设计优秀**：
本轮重新建立视觉质量基线，不受此前 VERIFIED 状态约束。

### 观察（真实运行 + 截图）

- 环境：Go 后端 `:8080`（真实媒体库 104 相册 / 28 集合）+ Vite `:5173`，
  Playwright Chromium，**DPR=1、浏览器缩放 100%**（先验证，排除"截图误判"的可能）。
- 基线截图 32 张：`frontend/.smoke/base0/`（明暗 × 390/768/1440/1920 × 4 页）。
- 量化基线：`npm run audit:layout`（本轮新增脚本）。

### 批评

**专业设计师视角**

1. 首页没有主角。"图像库"这个导航性词汇以 30px 占据视线最重的位置，而真正的主角
   （在读的那本书的封面）只有 140×176，被塞进一个 1340×200 的灰色横幅里，
   右侧 1000px 是空的。
2. 层级倒置：30px（页面框架）> 15px（区块标题）> 13px（卡片标题）。
   **界面比内容大**，这正是"像后台"的技术成因。
3. 版面是"等分网格堆叠"：未读 6 张 + 在读 5 张，同尺寸同密度连成一片 11 张卡的墙，
   没有任何主次节奏。
4. 视频封面是灰底空框 + "▶ —"，是全页最像"文件损坏"的地方。

**普通用户视角**

1. 打开应用，标题写着"图像库 / 104 本相册 / 28 个集合" —— 像磁盘清理工具的统计页。
2. "接着读上一本"确实在第一屏，但那条横幅长得像加载失败的空面板。
3. 搜索框缩在左上角，右边一大片空顶栏，不知道该点什么。
4. 有 3 张卡是灰的，以为文件坏了。

### 量化结论

| 指标 | 实测 | 判定 |
|------|------|------|
| 1920px 主内容占视口 | 75%（1440/1920），左右各 240px 死白 | **A 成立** |
| 1440px 主内容 | 85.6%（受 208px 侧栏挤压，无额外死白） | A 在超宽屏才成立 |
| 主导文本字号 | 12.5px × 95 处（首页可见文本的最大宗） | **B 成立**（不是浏览器缩放问题） |
| 最低字号 | 10.5px（kbd）、11.5px（badge / 状态字） | B 集中在"主内容是 meta"而非"全部都小" |
| 控件高度 < 28px | 首页 18 处（含 6 个 24px 的年份筛选按钮） | B 的可操作面证据 |
| 横向溢出 | 0（5 档 × 明暗 × 4 页全绿） | 无回归风险 |
| DPR / 缩放 | 1 / 100% | 已排除"截图缩放误判"这一根因 |

**A、B、C、D、E、F 六条假设全部成立**，但根因各不相同：
A 是容器上限；B 是字号分配（主内容被当成 meta 处理）；C 是构图（横幅而非封面墙）；
D 是信息架构（框架 > 内容）；E 是封面策略单一；F 是层级倒置。

### 构思（本轮方向）

针对首页提出两个有实质差异的方案：

**方案 A ——「编辑式封面台」**：
继续阅读不再是横幅，而是**一张大海报 + 右侧信息栏**：封面放大到 ~320×400，
标题与 CTA 紧贴封面右侧，整体宽度自适应（约 760px），其余在读书目降级为右侧小海报列。
信息结构：主角 → 次要 → 其它。
优点：改动局部、聚焦、CTA 距离最短；缺点：仍是一个"卡片"，横向仍留一段空白。

**方案 B ——「胶片带 / 封面墙」**：
继续阅读改为一整条**海报带**（filmstrip）：所有在读相册按统一高度（200–260px）横排，
**宽度按各自长宽比自适应**，第一本更高（280px）形成主次。下方未读区同理，
但高度更矮（160px）。时间线降为"年份筛选带"。
优点：内容成为主角、长宽比问题自然解决、横向空间被真正用满、有辨识度；
缺点：需要拿到封面原始宽高比（后端是否提供？需确认）；横向溢出/窄屏需要额外处理。

→ **决定：Cycle 1 采用方案 B 的核心（封面带），但保留方案 A 的"主角更大"原则。**
先确认后端是否能提供封面宽高比。

## R1 · 首页封面台与视觉基线重设（2026-11-03）

### 假设

1. 首页不需要"横幅"这种形态。横幅天然要求内容横向铺满，而信息量不足以铺满，
   于是必然出现空洞。把主角从"横幅"换成"一张大封面"，空洞自然消失。
2. 内容没有存在感，一半来自**比例错配**：主封面比它自己的次级卡还小。
   把主封面放大到货架海报的 1.6 倍以上，层级会立刻清晰。
3. 容器上限与标题层级是可量化的硬伤，改掉即可，不需要靠"感觉"。

### 备选方案（比较）

| 方案 | 结构 | 取舍 | 结论 |
|------|------|------|------|
| A「编辑式封面台」 | 一张大封面 + 紧贴其右的信息栏 + 其余在读降级为小海报列 | 改动局部、CTA 距离最短；但右栏仍有留白 | **采用（与 B 合并）** |
| B「胶片带 / 封面墙」 | 所有在读按统一高度横排、宽度按各自真实比例自适应 | 封面比例问题解决得最彻底；但需要后端提供封面宽高比 | **部分采用**：后端目前不提供宽高比，改用"按媒体类型定比例"（图片 2:3 / 视频 16/9），避免为了排版去改后端契约 |
| C「左轨 + 沉浸封面墙」 | 左侧 300px 固定"在读轨"，右侧封面墙铺满 | 接近独立评审推荐的方案 B；能彻底利用宽度 | 下一轮候选：需要处理双滚动区与"最近"页语义重叠 |

### 实施（提交 `8ec71ce`）

- 继续阅读 → **封面台**：300×450 的 2:3 主封面（走 `/api/previews` 640px，
  避免放大 320px 缩略图）+ 墙签式标题 + 紧贴封面的进度读数 / 进度条 / 主操作
  + 其余在读的横向货架。
- 未读 → **横向封面货架**（图片 2:3、视频 16:9），右端渐隐提示还有更多。
- `.page-shell` 上限 1440 → 1600，padding 改 `clamp(16px, 2vw, 40px)`；
  新增 `.hero-title`（26px）、`.section-title` 15 → 17px、`.btn-sm` 30 → 32px。
- 顶栏图标组贴到视口右缘；顶栏内层复用 `.page-shell`，与正文共用左基线。
- 网格列数由固定 6 列改为 `auto-fill minmax(164px, 1fr)`。
- 视频封面 letterbox 底色改用新令牌 `--bg-media`（恒深色）。

### 验证

| 项 | 前 | 后 |
|----|----|----|
| 1920px 主内容宽度 | 1440px（视口 75%，主区 84%） | **1600px（视口 83.3%，主区 93.5%）** |
| 主封面尺寸 | 140×176（比次级卡还小） | **300×450（货架海报的 1.67 倍）** |
| CTA 与封面的视觉距离 | ~1000px | **~60px**（同在左栏） |
| 控件 < 28px | 18 处 | **2 处** |
| 横向溢出 | 0 | 0 |
| 对比度 AA | 全绿 | 全绿 |
| 单测 / Lint / Build | 582 绿 / 0 error / 通过 | 同 |

截图：`.smoke/base0/`（前）→ `.smoke/r1c/`（后），明暗 × 4 断点共 32 张。

### 前后差异（逐张看图得到的具体事实）

- **light-1920-home**：旧版首屏是一块横贯 1340px 的浅灰盒子，右侧约 1000px 只有
  一颗按钮和一颗 ×；新版首屏左侧是一张 300×450 的清晰封面（图片走预览接口，
  不再是放大的缩略图），右侧信息与封面同屏，主按钮紧贴标题。
  旧的"顶栏图标停在 x=850、右侧空 1000px"变成图标贴到 x=1900。
- **light-1440-home**：旧版主封面只有货架海报的一半大；新版主封面 1.67 倍于
  货架海报，"继续阅读 / 其余在读"的主次一眼可分。
- **dark-1440-home**：旧版横幅在深色下是一整块纯黑空洞；新版深色下封面与
  背景分离清晰，货架右端渐隐提示"还有更多"。
- **未读区**：旧版 6 张卡里 3 张是灰底空框（视频 letterbox 落在浅灰底）；
  新版视频卡是深色画布 + 圆形播放徽标 + "正在加载…"，有明确的图形语言。

### 踩过的坑（写下来防止重蹈）

1. **Tailwind 工具类名**：令牌叫 `--bg-media`，而颜色键是 `bg-media`，
   工具类因此是 `bg-bg-media` 而不是 `bg-media`。写错时**样式表里根本不存在这条规则**
   （computed background 直接是 transparent），不报错、只是没效果 ——
   排查时先在浏览器里查 `document.styleSheets` 里有没有这条规则，别急着怀疑 HMR。
2. **新增 Tailwind 颜色需要重启 dev server**：`tailwind.config.ts` 改动后
   已运行的 Vite 进程不会重新生成工具类。改完配置要重启前端。
3. **`networkidle` 在这个应用里不可用**：页面含 SSE 长连接，且 `/api/previews`
   首次生成预览图可能耗时数秒。截图 / 审计脚本改用
   `domcontentloaded` + 等待 `document.images` 解码完成。
4. **主封面用缩略图会糊**：`/api/thumbs` 走 `imaging.Fit(320, 350)`，
   最大边只有 320px。300px 宽的主封面必须走 `/api/previews?w=640`。

### 下一轮重点

- 侧栏中段大片空白（B8）、"随机一本 / 随机未读"与首页按钮重复；
- 顶栏搜索权重仍偏低（B7）；
- 「最近 / 收藏 / 未读」三页与首页同构，缺少语义差异（B13）；
- 未读货架右侧仍有约 375px 空档，需要决定"留白"还是"补内容"。

## R2 · 导航、封面台收口与页面一致性（2026-11-03）

### 假设

1. 侧栏中段的空白不是"侧栏太窄"，而是**没有一个值得放在那里的东西**。
   与其把导航摊开，不如把全局最高频的动作（接着读）钉在侧栏底部。
2. 首页之外的几页之所以"像后台"，是因为它们都只是**同一张卡片的网格**，
   而视频相册页干脆是**一套独立的写死样式**（另一套标题字号、另一套按钮）。
3. 不同宽高比的媒体要真正区分，区别点不在"裁切方式"，而在**给它们各自的画幅**。

### 备选方案（比较）

| 问题 | 方案 A | 方案 B | 结论 |
|------|--------|--------|------|
| 侧栏空白 | 收窄侧栏到 176px | 底部加「接着读」迷你卡 | **采用 B**：空白不是尺寸问题，是内容问题；且"接着读"是全局最高频动作 |
| 视频画幅 | 4:5 格里 `object-contain` | 视频单独用 16:9 画幅 | **采用 B**：竖框框宽银幕必然留边，留边是噪音 |
| 页网格取景 | `object-contain` 整页显示 | `object-cover` + 偏上取景 | **采用 B（并撤销先做的 A）**：整页显示让横构图照片在竖格里留下大片上下灰边，整页网格变成一堆灰框；实测后回退 |
| 视频相册页标题 | 保留 28px 独立样式 | 复用 `.page-title` / `.btn` | **采用 B**：同一应用两套标题字号会让"标准"不可预期 |

### 实施（提交 `3562f64`）

- **侧栏**：底部新增「接着读」迷你卡（封面缩略图 + 标题 + 进度条 + 页码），
  数据来自与首页同一个 dashboard 查询（React Query 共享缓存，不额外请求）；
  移除与「未读」页 / 首页重复的「随机未读」按钮。
- **跳转逻辑抽公共函数** `utils/continueReading.ts`（首页封面台与侧栏迷你卡共用），
  避免两处生成不同的 URL。
- **首页页标题让位**：新增 `.page-title--compact`（24px），首页标题不再是全页最大字号，
  主角标题 `.hero-title`（26px）成为最大的字。
- **视频角标**：时长未知时不再显示 "—"（破折号看起来像"读不出来 / 坏了"），只留播放图标。
- **封面取景**：相册封面统一偏上取景（`object-position: 50% 25%`），漫画封面的标题与
  人物头部不再被裁掉。
- **媒体画幅**：纯视频网格改 16:9 + 深色媒体画布；混合网格里视频格用深色画布；
  视频相册页的大封面同样用深色画布。
- **视频相册页 hero**：标题改用 `.page-title`，按钮改用 `.btn` 系列，
  CTA 从标题下方移到同一行的右端（原位置让整行右侧空掉一大片）。
- **货架容量**：继续阅读的货架从 5 本扩到 10 本（宽屏上 6 本只占半行，右侧像"排版没做完"）。

### 踩过的坑

1. **`object-contain` 的代价**：整页显示看起来"更忠实"，但横构图照片在 3:4 竖格里

2. **对比度审计会抓到新组件的小字**：侧栏迷你卡用 `text-fg-subtle` 压在

   → 教训：新增"卡片套在非默认底色上"的组件时，先想一遍底色组合。

## R3 · 页面语义差异、密度分级与收尾核对（2026-11-03）

### 假设

1. 「最近 / 未读 / 收藏 / 全部图像」看起来一样，是因为它们**只有标题不同**，
   下面都是同一张 4:5 的密集网格。语义差异应该体现在**画幅与密度**上：
   收藏是"精选陈列"，未读是"待办清单"，全部图像是"浏览"。
2. 卡片 meta 行 12.5px 是"内容存在感不足"的最后一块：首页可见文本里
   12.5px 曾占 95 处（绝对多数）。
3. 剩下两条被记为"问题"的条目，可能根本不是问题 —— 需要实测而不是推测。

### 实施（提交见下）

- **AlbumGrid 新增 `coverRatio` / `cardMinWidth`**：收藏页改为 2:3 海报比例 +
  224px 疏朗网格（精选陈列），未读 / 最近 / 全部图像保持 4:5 + 164px 密集网格
  （清单与浏览）。这是三页之间第一次有**结构性**而非标题性的区别。
- **卡片 meta 行 12.5px → 13px**：首页 12.5px 文本从 95 处降到 62 处，
  13px 从 18 处升到 45 处。
- **实测核对两条疑似问题**：
  - B12「状态栏切边」→ **不是问题**。实测 `main` 的下边界与状态栏上边界同为 868px
    （两者是 flex 兄弟，不存在覆盖），滚到底后最后一行完整可见。
    截图 `.smoke/r3/recents-bottom.png`。
  - B14「阅读器顶栏在亮图上不可读」→ **不是问题**。顶栏已带 `.scrim-top`
    （黑色 88% 覆盖到 62% 高度），实测 computed backgroundImage 生效，
    截图 `.smoke/scrim-top.png` 显示白字在亮图上清晰可读。
    → 教训：**审计结论要复核**。上一轮把"阅读器亮图可读性"列为遗留问题，

## R4 · 收尾：填掉三处留白与一处破图（2026-11-03）

### 假设

上一轮结束时仍有四条未解决：侧栏中段空白、顶栏老式布局、收藏页空状态 90% 空白、
时间线没改成胶片带。本轮逐一处理，并假设：

1. 侧栏的空白**不是尺寸问题而是内容问题** —— 侧栏刻意不下载全库摘要
   （`useLibrary` 里写明"常驻侧边栏只需要未读计数"），所以不能塞"年份索引"，
   但**dashboard 里已有的 32 本在读**可以拿来填。
2. 顶栏中间空是因为顶栏只有"搜索 + 三个图标"，没有一个左槽。给它一个
   **全局上下文**（库规模），并把搜索居中，顶栏就成了有结构的应用栏。
3. 年份卡的 2×2 马赛克在 240px 的格子里每块只有 ~85px，全是看不清的缩略图 ——
   宽幅单张代表封面既清楚，又更像"按时间排列的一格格胶片"。

### 实施（提交见下）

- **侧栏**：导航组之后新增「继续阅读」区 —— 一张主封面卡 + 最多 5 条紧凑行
  （26×34 缩略图 + 标题 + 页码）+ "还有 N 本没看完"；底部改为弹性留白，
  设置 / 随机一本 / 状态沉到最底。侧栏中段不再空。
  数据全部来自已在手的 dashboard 查询，**不新增任何请求**。
- **顶栏**：改成三段式 —— 左槽「104 本相册 · 28 个集合」（全局上下文）、
  中槽居中的胶囊形搜索、右槽全局动作。库规模同时从首页页头与底部状态栏
  移除（同一事实只出现一次）。搜索框改胶囊形 command bar。
- **时间线**：年份卡从 4:5 竖向海报 + 2×2 马赛克改为 **16:9 宽幅胶片条**：
  一张代表封面铺满整格 + 左上年份大字 + 左下统计 + 右上漏斗。
  年份格子从"一屏两行"变成"一屏三行"，时间线整段高度减少约 40%。
- **未读货架**：卡片宽度改为 `flex-1 + min/max` —— 条目少时撑开铺满整行
  （1920 下不再有 450px 空档），条目多时保持最小宽度并横向滚动。
- **空状态**：`EmptyState` 挂上 `page-shell`，与正文用同一条左基线
  （此前居中的是"整个主区"，有侧栏时整块空态偏左）。
- **收藏页失效收藏**：空态补图标 + 「清理 N 项失效收藏」按钮
  （失效条目永远渲染不出来，留着只会让收藏页一直空着）。
- **修掉一处真实缺陷**：年份代表封面可能是已删除的文件（404）或无法解码的
  格式（415）—— 原先直接渲染 `<img>`，露出浏览器破图图标（2023 那格就是）。
  现在降级成"年份 + 计数"的纯色卡。
