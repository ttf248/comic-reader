> 本文件是 Local Gallery 的长期设计基线：产品定位、信息架构、视觉语言、交互原则，
> 以及**明确不采用**的设计模式。

## 1. 产品定位

**一句话**：一个把本地照片、漫画与视频收纳成「可以沉浸式浏览与阅读的个人画廊」的本地应用。

**它不是什么**：

| 不是 | 原因 |
|------|------|
| 文件管理器 | 用户来这里是为了"看"和"读"，不是管理目录结构；路径、扩展名、大小属于次级信息 |
| 素材库后台 | 表格化、密度优先、控件优先的界面会把内容挤到次要位置 |
| 云相册 | 无账号、无上传、无分享；离线本地是核心卖点，不该模仿云服务的空状态 |
| 漫画阅读器的下载站 | 内容已在本地，重点是"重新发现"和"接着读" |

**三个必须做好的场景**（按优先级）：

1. **接着读** —— 打开应用 3 秒内进入上次看到的那一页；
2. **随便翻翻** —— 没有明确目标时也能被内容吸引（随机一本 / 未读推荐 / 时间线）；
3. **找到某一本** —— 搜索、标签、年份、收藏四种路径都成立。

## 2. 设计方向

### 2.1 内容优先（Content First）

- **封面是主角**：任何一屏里，图像的视觉重量必须大于界面框架。禁止出现"大面积留白 + 小图 + 文字"的版面。
- **界面退到背景**：界面元素只在被需要时出现（hover、聚焦、选中）。默认状态应该是"安静的纸面 + 摊开的照片"。
- **一屏一主角**：首页首屏必须有一个明确的视觉主角（当前在读的那一本），而不是若干个同权重的方块。

### 2.2 辨识度（Identity）

不做"又一个管理后台"。辨识度来自三件事：

1. **版面节奏**：编辑式排版（大图 + 明确的字号阶差 + 有意图的留白），而不是等分网格堆叠；
2. **材质克制**：页面是纸面，只有浮层（菜单 / 弹窗 / 悬停预览）才有边框和阴影；内容区靠留白与字号分组；
3. **强调色节制**：强调色只出现在"主操作 / 选中态 / 进度"三处，永不做装饰。

### 2.3 舒适（Comfort）

- 中文正文最小 **13px**，辅助信息最小 **12.5px**；禁止 12px 以下的中文。
- 交互控件最小高度 **28px**，主要操作 **36px**，触控场景 **44px**。
- **视觉尺寸与命中区可以分开**：开关这类控件的"外观"可以是 20px 的小药丸，
  但外层按钮必须撑到 28px（视觉居中）。达标不一定要靠放大外观 ——
  放大外观会破坏版式，而撑开命中区不会。
- **图标（非文本内容）对比度 ≥ 3:1**（WCAG 1.4.11）：压在照片上的图标必须
  有恒定的局部底色，不能"看照片脸色"。图标没有文字节点，审计要单独开通道。
- 动效 120–320ms，只做位移 / 透明度 / 缩放三类，不做花哨路径。
- 尊重 `prefers-reduced-motion`。

### 2.4 自然（Natural）

- 常用动作一步可达；次级动作收进菜单，但**入口本身必须看得见**。
- 键盘、鼠标、触摸三路都能完成主流程；不依赖 hover 才能发现的功能。

## 3. 信息架构

```
Local Gallery
├─ 图像库 (/)              ← 主页：接着读 + 未读推荐 + 时间线 + 全部图像
│   ├─ 继续阅读            ← 最高频任务，视觉主角
│   ├─ 未读推荐            ← 次高：下一本读什么
│   ├─ 时间线（按年份）    ← 随机探索的主轴
│   └─ 全部图像            ← 全量网格 + 视图/排序/年份筛选
├─ 最近 (/recents)         ← 回来过的
├─ 收藏 (/favorites)       ← 主动标记的
├─ 未读 (/unread)          ← 完整未读库（分页）
├─ 文件夹详情 (/albums/:id) ← 单本的封面墙 + 进入阅读器
├─ 阅读器 (/gallery)       ← 沉浸式，只留必要控件
└─ 设置 (/settings)
```

**浏览轴**只有三条：**时间（年份）**、**状态（未读 / 在读 / 已读）**、**显式标记（收藏）**。不引入标签体系之外的第四种轴。

## 4. 视觉语言

### 4.1 排版

| 角色 | 字号 / 行高 | 字重 | 用途 |
|------|------------|------|------|
| `display` | 30–34px / 1.15 | 650 | 页面主标题（仅一处） |
| `hero` | 22–26px / 1.25 | 650 | 首页主角标题 |
| `section` | 17px / 1.4 | 600 | 区块标题 |
| `title` | 14–15px / 1.4 | 550–600 | 卡片 / 列表项标题 |
| `body` | 14–15px / 1.6 | 400 | 正文、说明 |
| `meta` | 12.5–13px / 1.45 | 400 | 统计、时间、路径、提示 |

- 中文不使用 `uppercase` + 大字距做标签；层级靠**字号 + 字重 + 颜色**三段式表达。
- 数字用 `tabular-nums`，避免计数跳动。
- **层级反了是最严重的错误**：界面框架的字号不得大于内容标题的字号。

### 4.2 色彩

- 主题 token 定义在 `frontend/src/styles/tokens.css`，Tailwind 工具类只做语义引用，**不硬编码 hex**。
- 表面层级：`bg`（纸面）→ `bg-elevated`（浮层）→ `bg-subtle`（次级分区）→ `bg-inset`（卡内底）→ `bg-strong`（最强分区）。
- 强调色由 `--accent` 驱动，用户可切换（graphite / indigo / rose / forest / ochre / plum），明暗两套各自取值。
- 文字压在图片上时必须加**局部高不透明度蒙版**（`.scrim-top` / `.scrim-bottom`）或描边（`.text-on-media`），禁止假设图片是暗的。

### 4.3 层级与密度

- **一屏一主角**：首屏只允许一个视觉主角（首页是"在读的那一本"的主封面）。
- **主角 / 次要 / 其它三档**：主角封面高度 ≥ 次级海报的 1.6 倍；
  数字与照片的权重必须一眼可分。
  **这条规则必须在所有断点都成立**（含手机）：手机上主角封面曾只有
  112px，而"其余在读"的封面是 172px —— 主角比次级还小，"一屏一主角"
  直接失效。窄屏的做法见 §4.3.1。
  **例外**：首屏高度受限的档位（≤880px 高，或舞台竖排的平板档）比例
  实测在 **1.52~1.58**，可降到 ~1.5；但两栏宽度比例不动 ——
  缩左栏会让右栏变大、次级封面跟着变大，主角/次级比例反而被稀释。
  提比例的**正确杠杆是压小次级海报**（右栏网格加一列），不是缩小主角：
  主角一缩就要和"主操作被首屏裁掉"（§4.3.1）抢高度。
- **同一事实只出现一次**：库规模放在顶栏左槽，首页页头与底部状态栏都不再重复。
- **货架按条目数自适应**：条目少时撑开铺满整行，条目多时保持最小宽度并横向滚动，
  右端用渐隐提示"还有更多"。固定列数 + 固定卡片宽会在宽屏上留下大片空档。
- **文字栏不能靠留白撑满**：一段文字放在比它宽得多的栏里，剩下的就是空洞，
  不是留白。**要么让内容本身是图像，要么把栏收窄到内容宽度** ——
  两栏版式里，右栏必须由图像占位（封面网格），不能是"读数 + 按钮 + 一片空"。

### 4.3.1 首页「继续阅读」舞台：左栏封面台 + 右栏封面网格

```
┌──────────┐   其余在读
│  主封面   │   ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐
│  2:3     │   └──┘└──┘└──┘└──┘└──┘└──┘
└──────────┘   ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐
 墙签标题      └──┘└──┘└──┘└──┘└──┘└──┘
 看到 N / M
 ▓▓▓▓░░░░░░
 [继续阅读] [标记为已读]
```

- **左栏**：主封面（2:3，320~352px）+ 墙签标题 + 进度读数 + 进度条 + 操作。
  主操作必须在封面正下方（< 100px），不能推到右栏尽头。
- **右栏**：整栏都是"其余在读"的封面网格。1920 下 6 列 × 2 行 = 12 张；
  网格条目上限 **12**（可被 2/3/4/6 列整除，各断点都不出现半行），
  窄屏用 `nth-child` 规则裁到 4 条、1800px 以下裁到 8 条。
- **列数写死，不用 auto-fill**：右栏宽度 = 视口 − 侧栏 − 左栏，
  auto-fill 在 1280~1800 之间会切出忽大忽小的列宽（150px ↔ 246px）。
- **列数与条数必须成对，且写在同一处**（global.css 的 `.stage-grid`）：
  4 列配 8 条、5 列配 10 条、6 列配 12 条 —— 各断点末行都是满的。
  分成两处维护（列数在 CSS、条数在 React）就会出现"5 列只排 8 条、
  末行只剩 3 张"的半行。**注意 Tailwind 的层叠顺序**：工具类
  （utilities）压得过组件类（components），所以在 CSS 里写
  `display: block` 想解除 React 侧 `hidden` 是**无效**的 —— 要么把裁剪
  规则整个搬进 CSS，要么就别分两处。
- **次级海报的列数是主角比例的杠杆**：1024 档主封面 328px 高，
  4 列的次级海报有 275px —— 比例只有 1.19，主角几乎没拉开；
  改 5 列后次级海报 216px，比例回到 1.52（见 §4.3）。
- **右栏不能空**：只有一本在读时右栏没有"其余在读"，改放「未读」
  （"你正在读的"与"接下来读的"并排）；两样都没有时，舞台改成
  "主封面 + 信息"并排的紧凑块。**任何情况下都不要让右栏空一整屏。**
- **flex 行的子元素要有宽度约束**：右栏内容（根元素带 `width:100%`）
  不裹 `flex-1 min-w-0` 就会撑开整行，横向溢出可达 200px 量级。
- **舞台必须整体落在首屏里**：主操作「继续阅读」是全站最高频的任务，
  它的底边不能被主区（滚动容器）的下沿裁掉。1440×900 这类常见笔记本
  高度上，320×480 的封面 + 墙签 + 进度 + 按钮共 671px，会超出主区可用
  高度（实测超出 33px，按钮只剩 3px、箭头整个不可见）。
  封面上限因此写成**连续函数**而不是媒体查询分档：
  `--stage-cover-h: clamp(240px, calc(100dvh - 440px), 480px)`
  （≥1536px 时上限 528px）。分档会在断点附近出现"差 1px 就放不下"的
  临界翻转（1440×900 用 320px 正好超出 1px）。
  **左栏宽度固定，只让封面在栏内收窄**；墙签宽度跟随封面。
  短屏时右栏网格改 5 列 10 条（`.stage-grid`），把主角/次级比例拉回 1.58。

- **窄屏（<1280）是另一套舞台结构**："封面 + 墙签并排 + 右栏网格在下面"。
  这套结构下：
  - 手机（<640）：封面 150px，**墙签与封面并排**（另起一行时封面右侧会
    空出 246px，主操作也被推到整屏下方）；"其余在读"退成 **4 张的缩略图带**
    （`.stage-grid` 手机档 4 列），否则次级封面比主角还大。
  - 平板（768~1279）：封面跟随 `--stage-cover-w`；墙签列限宽
    `md:max-w-[440px]`，否则标题右侧会空出约 355px，进度条被拉成一条
    755px 的长线。
  - 窄屏档不要"缩封面"：这套结构里封面缩小只会让页面更空，
    要加的是**并排**。

### 4.4 应用框架（顶栏 / 侧栏）

**顶栏 = 三段式应用栏**：左槽放**全局上下文**（媒体库规模）、中槽放**搜索**（居中，
胶囊形 command bar）、右槽放**全局动作**（帮助 / 主题 / 更多）。
只有"输入框 + 几个图标"的顶栏，中间会空出六七百像素，看起来像被遗弃的控件区。
阅读器（沉浸场景）例外：顶栏只留返回 / 名称 / 页码 / 收藏 / 全屏 / 更多。

**侧栏 = 四段**：品牌 → 主导航 → **内容区**（继续阅读）→ 弹性留白 → 页脚（设置 / 随机）。
侧栏刻意**不下载全库摘要**（见 `useLibrary` 注释），所以内容区只能用
dashboard 已经带在手上的数据；**留白本身不是缺陷，空白夹在导航与内容之间才是**。

**空态必须和正文共用左基线**：`EmptyState` 挂 `.page-shell`，
居中的是"内容列"而不是"整个主区"。

**空态要给出下一步的对象，不只是下一步的按钮**：收藏为空时与其写
"去主页看看"，不如直接把可以收藏的对象摆出来（一排真实封面 + 常驻的
星标）—— 文案在教用户点哪个控件，那个控件就必须看得见
（星标默认 hover 才露出，教用户点它时要显式常驻）。
空态下方还有内容时用 `EmptyState` 的 `dense` 档（最小高度 52vh → 30vh），
否则推荐位会被推到首屏之外。

**浮层必须浮在正文之上**：顶栏带 `backdrop-blur`，自成一个层叠上下文 ——
面板里的 `z-30` 只在顶栏内部有效，出不了顶栏。所以**顶栏本身**要
`relative z-30`（相对正文），下拉才能盖住封面与网格。
凡是"下拉被内容盖住"的 bug，先查是不是父级 `backdrop-blur` /
`transform` / `filter` 造出的层叠上下文，而不是给面板继续加 z-index。

### 4.5 容器与留白

- `.page-shell` 是唯一的页面容器：随视口流体伸缩，宽屏上限 **1600px**，左右 padding `clamp(16px, 2vw, 40px)`。
- **禁止嵌套 `.page-shell`**（历史上 `YearTimeline` 曾在 `page-shell` 里再套一层，导致该区块凭空多出 32px 缩进）。
- 分组靠**留白 + 字号**，不靠边框盒；只有浮层和确实需要的表单分组才用 `.panel`。

### 4.6 封面与不同宽高比

媒体库天然混合三种比例，必须差异化处理，而不是一律 `aspect-[4/5] + object-cover`：

| 类型 | 处理 |
|------|------|
| 漫画封面 / 竖构图 | 保持**海报比例**（2:3），`object-cover` + `object-position: 50% 25%`（保留页面上半部分的标题与人物头部） |
| 普通照片 | 按所在网格的画幅裁切，构图重心保持中上 |
| 视频 | 固定 **16:9** 画幅（纯视频网格直接用 16:9 格，不塞进竖格）；letterbox 底色用 `--bg-media`（恒深色），抽帧失败时给出有设计感的占位（深色画布 + 圆形播放徽标 + 文案），不留灰底空框 |

**画幅即语义**：同一张网格里，画幅要跟着页面的任务走。

| 页面 / 区块 | 任务 | 画幅 | 密度 |
|-------------|------|------|------|
| 首页「继续阅读」主封面 | 接着看这一本 | 2:3，**至少是网格海报的 1.6 倍** | 单张 + 右栏封面网格（≤12 张） |
| 首页「未读」货架 | 下一本读什么 | 图片 2:3 / 视频 16:9 | 横向货架 |
| 「全部图像」网格 | 浏览全库 | 4:5 | 密集（列宽下限 164px） |
| 「未读」页 | 待办清单 | 4:5 | 密集（164px） |
| 「最近」页 | 时间序回看 | 4:5 + 「上次 X」时间戳 | 密集（164px） |
| 「收藏」页 | 精选陈列 | 2:3 | 疏朗（列宽下限 224px） |
| 相册详情页页网格 | 认页 | 4:5，偏上取景 | 由 S / M / L 切换 |
| 首页时间线年份卡 | 按年浏览 | **16:9 宽幅胶片条**，单张代表封面 | auto-fill，minmax 196px |

**宽幅格子不拼马赛克**：240px 的年份格里做 2×2 拼接，每块只有 ~85px，
全是看不清的缩略图，读起来像"一片糊"。宽幅单张代表封面既清楚，
又更像按时间排列的一格格胶片。

**取不到图必须降级，不能露破图**：代表封面可能是已删除的文件（404）
或无法解码的格式（415）。所有封面位都要有 `onError` 兜底，
降级成有设计感的占位（纯色卡 + 关键信息），而不是浏览器的破图图标。

### 4.7 压在图片上的文字

白字压在照片上时，底色必须是**不透明段**，不是"看起来够黑的渐变起点"：

| 场景 | 做法 | 实测 |
|------|------|------|
| 阅读器顶栏 | `.scrim-top`：0.88 黑，不透明段覆盖到 62% 高度 | 白字压纯白图 8.9:1 |
| 阅读器底栏 | `.scrim-bottom`：0.88 黑，不透明段覆盖到 **68%** | 白字压纯白图 8.9:1 |
| 视频缩略图的文件名 | `from-black/85 from-80%`：不透明段盖住整行文字 | 14.3:1 |

- **不透明段必须盖住整行文字**：44px 高的底栏里文字垂直居中，
  字形上沿会落进渐变过渡带 —— 那一小段底色只有 70% 黑，
  白字对比度掉到 4.4:1，压在 AA 线上。
- **审计量的是"文字外一圈"的像素**：改渐变时只看"底色够不够黑"会误判，
  要看文字包围盒外一圈的最不利一侧。
- **Tailwind 只认 5% 的整数倍渐变色标**：`from-78%` 会被静默丢弃
  （不报错，整条规则不生成），`from-55%` 才有效。

**压在图上的文字有两种结构，别只防一种**：

| 结构 | 例子 | 背板是什么 |
|------|------|-----------|
| **祖先层**：文字在图片 / 渐变蒙版的 DOM 子树里 | 阅读器顶栏底栏、年份卡的顶部渐变 | 那条蒙版本身 |
| **兄弟层**：文字靠负边距 + z-index 压在图上，**不在图的 DOM 子树里** | 标签页 hero 标题压在封面照片上 | 那张照片（蒙版只是半路盖了一层） |

只查祖先链的审计工具看不见兄弟层：它会把这类文字当成"压在纯色底上"，
结论可能与实际相反（白字压浅色照片，静态算 20:1、实际 1.4:1）。
**判定背板必须按绘制顺序，不能只看祖先链**（见 §8）。

**半透明角标（压在照片上的小色块）另有一条规则**：

- 角标底色半透明（`bg-bg-elevated/85`）时，**文字色必须用 `text-fg`
  这一级的主文字色，不能用 `text-fg-muted`** —— 角标底色跟着主题走，
  暗色主题下它是深色小块，muted 灰字压上去只有 4.49:1；
  底下的照片一亮（大白墙、白顶棚），实测只剩 **2.1:1**。
- 半透明意味着"底色 = 角标色 + 底下那张图"，所以对比度要按**最坏的一侧**
  算，不能按"底色通常是什么样"算。

### 4.8 虚拟网格：末行必须真的渲染出来

长列表用虚拟滚动（react-virtuoso）时，"拖到最底"必须能看到最后一行，
而不是一块灰色占位块。

- **Virtuoso 的整段滚动长度是估算的**，实测比真实布局高约两行。
  浏览器把 scrollTop 夹到真实底部，Virtuoso 以为底部还在下面，
  于是末行落在渲染窗口之外。
- **`itemSize` 对 `VirtuosoGrid` 无效**（那是 Virtuoso 列表的 prop，实测 0 次调用）；
  把 CSS grid 的行间距挪进格子也不影响估算值。
- **有效解法是 `increaseViewportBy`**：把虚拟窗口下沿多留一截
  （实测 `{top: 720, bottom: 720}`），估算误差被覆盖。
  误差量级不随条目数线性增长，一个固定余量就够。
- **但余量不能贪心**：下沿留到 1600px 时，Virtuoso 会在一帧里测量过多条目，
  它内部的尺寸树是**递归展开**的，直接爆栈
  （`Maximum call stack size exceeded`，405 个视频的相册一进页面就崩，
  整页被错误边界接管）。720px 同时满足"末行能渲染"与"不爆栈"。

### 4.9 阅读器：暗场约定

阅读器的画布恒为深色（`bg-neutral-950`），**阅读器里出现的每一个浮层
都必须跟着暗**：

| 浮层 | 做法 |
|------|------|
| 顶部「更多」菜单、右键菜单 | `Popover` / `ContextMenu` 的 `tone="reader"`：`bg-neutral-900/95` + `border-white/15` |
| 快捷键帮助 | `HelpOverlay` 的 `tone="reader"`，并用 `data-tone="reader"` 标记 |
| Toast | 按路由判断：`/gallery` 下走深色 |
| 图片信息面板 | 本来就是暗的（阅读器的既有约定） |

- **浅色卡片浮在黑底阅读器上 = "黑底里嵌一块白板"**：不只是难看，还会让
  两块浮层自相矛盾（信息面板暗、菜单亮）。
- **暗场浮层的焦点环要单独取色**：浅色主题的强调色恰好是近黑的石墨色
  （`--accent: #18181b`），焦点环会变成"黑底上的黑框"。所以暗场浮层用
  `[data-tone="reader"] :focus-visible { outline-color: rgba(255,255,255,.85) }`
  覆盖 —— 这条规则**必须不分层**写，未分层的声明才压得过 Tailwind 的
  `outline-none` 与全局 `:focus-visible`。
- **压在照片上的图标要有恒定底色**：白箭头直接压照片时对比度取决于照片
  内容（实测亮图上只有 2.34:1）。给图标配一枚深色圆底，
  局部背景恒定 → 7.03:1。

### 4.10 列表视图：按内容宽度切双列 / 三列

列表视图（未读 / 最近 / 收藏的"列表"模式）一行一条，右侧是右对齐的计数。
**单列时标题与计数会被拉到屏幕两端**，眼睛要横跨整屏才能对上：

| 视口 | 单列时 标题→计数 | 双列后 |
|------|----------------|--------|
| 1024 | 517px | 仍单列（见下） |
| 1280 | 763px | **233px** |
| 1440 | 917px | **310px** |
| 1920 | 484px（本来就是双列） | 484px |

**阈值按内容宽度定，不按视口宽度拍脑袋**：

```
内容宽 = 视口 − 侧栏 208 − 左右留白 80
1280 → 1072 → 双列每列 516 → 标题列还剩 350px，标题不截断  ✅
1024 →  816 → 双列每列 388 → 标题列只剩 222px，长标题被截断 ❌
```

所以阈值是 **`(min-width: 1280px)`**。放宽到 1024 看着"更充分利用空间"，
实际会把标题挤成省略号 —— 列表的价值就是能一眼读完标题。

**超宽屏（≥1600px）改三列**：两列时每列仍有 730px，标题与计数之间
隔着 484px —— 比 1440 档（310px）还远。三列要每列都不小于 ~400px
（缩略图 56 + 标题 200 + 计数 50 + 箭头 30 + 行内留白），也就是
内容宽 ≥ 3×400 + 2×40 = 1280 → 视口 ≥ 1600。实测 1920 下每列 469px，
标题→计数收到 223px，一屏从 14 条变成 21 条。

双列不是"把单列挤成两半"：每列内部仍然是 缩略图 + 标题 + 右对齐计数，
行高与单列一致，虚拟滚动按"每行 2 条"分组，行的 DOM 顺序仍是
从左到右、再换下一行（读序不变）。

### 4.11 设置页：网格线与行长是两件事

设置页的**内容左缘必须和其它页面落在同一条网格线上**
（1440 下 x=237、1920 下 x=302）。居中的窄列会让整页内容从列表页
切过来时横跳 237px（1920 下 416px）。

- **外层用全站标准的 `.page-shell`**（它自带 `margin-inline: auto`，
  删掉 Tailwind 的 `mx-auto` 没有用 —— 居中是组件层写死的），
  **内层再限宽**：外层负责"落在网格线上"，内层负责"一行别太长"。
- **≥1280px 改双列**（CSS 多列 + `break-inside: avoid`）：页面总高
  1440 下从 3171px（4 屏）降到 1839px（2.3 屏）。断点不能再低：
  1024 下每列只有 ~390px，"数据"分区的缓存卡片会被挤到换行。
- **卡片网格的列数跟容器走，不跟视口走**：`grid-cols-2 sm:grid-cols-5`
  这种视口断点在窄列里会把 5 张卡挤断字，要用容器断点
  （`auto-fit` + `minmax(112px,1fr)`）。

## 5. 交互原则

1. **悬停是增强，不是前提**：核心信息（标题、数量、进度）永远在静态状态下可读。
2. **进度可见**：阅读进度用**封面底边的一条线**表达，不用大块 chip 覆盖封面。
3. **反馈有层次**：hover 150ms 内起效、点击即时、异步操作有 toast。
4. **焦点可见**：所有可聚焦元素有 `focus-visible` 环，键盘路径完整可达。
5. **状态可解释**：未读 / 在读 / 已读三态来自真实数据（进度条、白点、✓），不编造状态。
6. **减少工具栏存在感**：全局顶栏只承担"搜索 + 全局动作"；页面级筛选贴近它作用的对象。

## 6. 明确不采用的设计模式

| 不采用 | 理由 |
|--------|------|
| 通用后台仪表盘（KPI 卡片 + 表格 + 侧栏折叠菜单） | 与"看内容"的目的冲突；会让首页像运营面板 |
| 每个模块套一个带边框的圆角盒子 | 层层嵌套的边框是视觉噪声，"留白即分组"更安静 |
| 灰白单色 + 16px 圆角 + 轻阴影 = "高级感" | 这是模板感不是辨识度；高级感来自排版节奏、材质与留白 |
| 封面一律 `object-cover` 塞进统一 4:5 | 裁掉漫画封面关键信息，横向照片被腰斩 |
| 侧栏铺满导航 + 侧栏底部放全局动作 | 侧栏应该短；全局动作属于顶栏 |
| 用 `uppercase` + `tracking-[0.18em]` 做中文标签 | 破坏汉字字距节奏，拉丁大写对中文无语义 |
| 首屏同时堆 3 个同权重 Hero | 视线无处落，"没有主角" |
| 工具栏常驻 7+ 个控件 | 顶栏只留搜索与全局动作，次级动作进菜单 |
| 视频封面抽帧失败时留灰色空框 | 空框会让用户以为内容损坏；应给出带图标的占位 |
| 深色主题只是把颜色反过来 | 暗色下要降低边框对比、提高图片与背景的分离度 |

## 8. 长期机制

- **每轮迭代都必须有截图证据**，产物放 `frontend/.smoke/<轮次>/`（已 gitignore）。
- **每轮收尾做一次全站复检**：8 个页面 × 5 档断点 × 明暗各拍一张，逐张看。
  单页审计看不出累积改动带来的层级问题 —— R8 就是靠它发现"手机上主角封面
  比次级封面还小"（比例 0.65），而这条规则在北极星里已经写了很久。
- **量化脚本入库**：`npm run audit:layout`（布局/字号）、`npm run audit:contrast`（对比度，含图标通道）、`npm run shot`（多断点截图）。
- **审计要有自检**：对比度脚本给每条通道配了"已知好坏"的样本
  （`npm run audit:contrast -- --self-test`）—— 工具自己分不清好坏时，
  它报"全部通过"就没有意义。
  **每加一条判定路径就要配对应样本**：R9 加了"兄弟层"与"半透明角标"
  两条路径，就补了四段样本（白字压白图 / 白字压黑图 / 深字压亮角标 /
  白字压亮角标），并且要求坏样本必须被判不合格、好样本必须被判合格。
- **审计的判定模型按绘制顺序，不按 DOM 树**：`elementsFromPoint` 不能用来
  找"画在下面"的东西（`pointer-events-none` 的蒙版不在列表里，实测会让
  首页年份大字被判成"白字压白底"，一次跑出 104 处假阳性）。
  正确做法是几何判定：列出所有图层（`<img>` + 带 `background-image` 的
  元素），比较层叠层级与 DOM 顺序。像素取样还要注意两件事：
  **盒子必须整个落在截图里**（视口外的元素取到的是透明像素，会被当成纯黑），
  **取样要落在背板那一层之内**（小角标的外扩取样环会跑到照片上）。
- **审计覆盖的路由要跟着功能一起长**：阅读器、相册详情页、标签页都是
  后加的入口，每个都要补伪路由（`album` / `reader` / `tag`），
  否则"已上线但没人量过"的页面会一直漏在体系之外（R9 的 B42 就是这种）。
- **审计要量"有效内容"而不是容器**：容器宽度 ≠ 内容宽度 —— 设置页的
  容器铺满 1600px，实际内容只有 768px 一列；只看容器宽度，
  "居中窄列"这类问题永远发现不了。布局审计因此多两个指标：
  **有效内容宽**（可见内容的并集）与**内容左缘**。
- **内容左缘必须跨页对齐**：同一断点下所有页面的内容左缘要落在同一条
  网格线上（阅读器是沉浸场景，不参与）。这条检查能自动抓住"整页居中
  窄列"这种问题 —— 把设置页改回居中，审计立刻会红。
- **审计要能区分"页面崩了"和"页面有问题"**：掉进错误边界的页面没有
  内容可量，报"全部通过"是假象。两个审计都新增了页面加载检查：
  掉进错误边界就重试一次，仍失败就单独报出来，不混进对齐比较。
- **审计要优先用真实数据**：标签页在真实库里有标签就用真的
  （`test-e2e.ps1 -Audit` 让审计能直接跑在带真实标签的临时库上），
  只有库里一个标签都没有时才伪造数据，并在输出里写明用了哪种。
- **审计脚本的伪路由必须跟真实入口一致**：阅读器用直接构造
  `/gallery?path=…` 进入，不靠点按钮（视频相册的按钮是「开始播放」，
  点不到就会静默跳过，量到的其实是相册页）。
- **文档同步**：每轮结束更新 `UX_ITERATIONS.md`（发生了什么、证据、失败尝试）与 `UX_BACKLOG.md`（状态流转）。
- **验收红线**：不得通过修改验收标准、删除断言、跳过失败用例来制造通过结果。
